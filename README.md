# GECKO LAB v1.2

모바일 세로 화면용 로컬 크레스티드 게코 브리딩 게임입니다. **플레이어가 턴을 마쳐야 진행되며, 1턴은 게임 시간 7일입니다.** 기존 멘델 유전·혈통·턴 규칙·PNG 원화를 보존하고, 새 개체는 상속된 60개 가상 좌위로 실제 무늬와 한국어 명칭을 계산합니다. 정식 외형은 명암 개선 v2 기반 **regional-2**입니다. 새 저장 v11을 사용하며 이전 저장은 자동 변경하지 않고 새 게임을 안내합니다. [정식 엔진 경로·관찰값·검증](docs/regional-engine.md).

## 실행

Node.js 24 LTS와 npm을 사용합니다.

```bash
npm ci
npm run dev
```

프로덕션은 `npm run build` 후 `npm run start`로 실행합니다.

- `/`: 컬렉션 홈은 현재 정렬·모프 필터의 **앞 6마리**를 3열×2행으로 표시합니다. 기본순 오른쪽 **격자 아이콘 → 전체 개체**에서 모든 개체를 검색·정렬·필터링하고, 카드 선택을 유지한 채 더보기의 상세·분양, 상태 버튼의 교배·사육장 관리와 하단 턴 진행을 연속으로 이용합니다. 검색·필터는 X 왼쪽 버튼으로 펼치며 기본은 접힘입니다. 상단에는 개체 선택과 독립적인 브리딩 도전 목표를 표시합니다. [화면·연속 관리·대량 개체 검증](docs/collection-manager.md). 컬렉션·인큐베이터·혈통도·상점은 같은 [공통 상·하단 UI](docs/common-ui.md)와 큰 **턴 넘기기** 버튼을 유지합니다.
- 컬렉션의 [상태·남은 턴·바로가기](docs/collection-status.md): 성장/휴식의 남은 턴을 표시하고 **브리딩 가능**은 해당 성별·ID가 선택된 기존 교배 팝업, **공간 확보 필요**는 기존 사육장 관리 팝업을 엽니다.
- 성체 상세의 **부모로 선택**, 또는 인큐베이터의 교배 탭에서 [교배 팝업](docs/breeding-risk.md)을 엽니다.
- `/lab`, `/lab/appearance`: 정식 `regional-2` 외형 갤러리. 96×96·8레이어·6개 기본 모프와 C/S/H 복합, 고정 시드·발현·파이어·정수 확대를 확인합니다. 구형 렌더러 전환은 없습니다.
- `/lab/appearance/candidates`: [원화 보존 후보 A/B/C 비교](docs/appearance-candidates/README.md). 같은 유전체·시드로 이전 정식·현재 v2·세 후보의 6모프와 저/일반/고발현을 비교합니다. 게임 엔진·저장·평가는 바꾸지 않는 별도 실험 화면입니다.
- `/lab/appearance/bases`: [원점에서 새로 만든 96px 베이스 A/B/C](docs/base-study/README.md). 얼굴·비율·자세가 다른 세 디자인의 기본/밝음/어두움/적은 무늬/많은 무늬와 48·72·96px, 다섯 게임 배치 모형을 비교합니다. 실제 게임과 연결하지 않습니다.
- `/lab/appearance/b-breeding`: [B · 브리딩 감상형의 유전 발현 실험](docs/b-breeding/README.md). B 원형을 유지한 6모프×3발현, 같은 모프의 다양성·명도·패턴·시드 차이, 기존 상속 함수로 생성한 부모/자손 3조합, 5세대 선택교배와 컬렉션 크기 비교입니다. 96×96 출력이며 정식 게임·저장·경제에는 연결하지 않습니다.
- `/lab/appearance/b-breeding/bases`: [B 내부 바디와 최종 표현형 분리 비교](docs/b-foundations/README.md). 현재·약한 패턴·패턴리스 내부 바디 위에 같은 일반 패턴과 6모프를 합성합니다. 일반 패턴 켜기/끄기, 96px·3배·모바일 카드 비교와 변경하지 않은 직전 B 대조군을 제공합니다.
- `/lab/patterns`: 유전형 기반 14개 실제 무늬·한국어 자동 명칭 비교. [구현·판정·근거·한계](docs/inherited-patterns.md).
- `/lab/breeding`: 별도 `phase2-lab` 슬롯의 이전 브리딩 회귀 시뮬레이터. 정식 `active` 게임과 분리됩니다.
- 개발 포트 3000, E2E 프로덕션 포트 3100. PWA 셸과 IndexedDB는 브라우저 로컬 저장입니다.

## 한국어 대표 모프명

게임의 모프 표시는 공통 규칙으로 **레드 릴리·트라이컬러 릴리·아잔틱·하이웨이**처럼 간결하게 표시합니다. 프라푸치노·루왁·릴리 아잔틱 등 확인한 복합명은 별도로 보존하고 불확실한 조합은 전체 설명식 명칭으로 표시합니다. 상세정보의 **전체 외형 분류**와 공개 유전정보에서 생략된 체색·무늬·공개 het 정보를 확인할 수 있습니다. 플레이어가 지정한 개체 이름과 유전 상속 규칙을 유지합니다. 대표 명칭은 정식 v2의 관찰값에서 계산하며 이름 자체에 별도 가격 프리미엄을 붙이지 않습니다. [규칙·국내 명칭 근거·폴백·불변 검증·모바일 캡처](docs/morph-display-names.md).

## 확정 턴·성장·급여 규칙

| 항목 | v1.2 동작 |
| --- | --- |
| 시간 | 버튼 1회 = 1턴 = 7일. 현실 시간·새로고침·재접속은 진행하지 않음 |
| 성장 | 부화 시 0턴, 6턴 아성체, **정확히 12턴 성체**. 성장 난수 없음 |
| 급여 | 턴 시작 시 보유 생존 개체 모두에게 사료 1개. 성장·번식 상태·하트와 무관 |
| 알 | 사료를 소비하지 않음. 해당 턴에 부화한 새끼는 다음 턴부터 소비 |
| 충분한 사료 | 자동 급여. 하트 최대 5까지 1 회복 |
| 사료 부족 | 턴 종료 전 경고·취소/사료 관리/진행 확인. 하트가 적은 개체부터 ID 순으로 급여 |
| 미급여 | 기존 컨디션 하트 −1, 0이면 영구 폐사. 판매 개체는 플레이어 사료 소비에서 제외 |

상단 먹이 +의 관리 창에서 사료를 확보하고 네 주요 탭에서 턴을 넘깁니다. 수동 추가 급여는 v1.2에서 사용하지 않습니다. 6턴의 아성체 구분, 하트 회복·부분 급여 순서는 게임용 보조 규칙이며 실제 사육 지침이 아닙니다.

개체 이미지는 기존 성장 단계에 따라 **해칭 50% / 아성체 75% / 성체 100%** 크기로 표시됩니다. 공통 Canvas의 CSS 표시만 바꾸며 카드·이미지 영역 크기, 원본 픽셀, 유전·성장·저장 규칙을 유지합니다. [적용 화면·검증·모바일 캡처](docs/growth-scale.md)를 참고하세요. 성장 크기 패치 당시의 타입·빌드·아트 해시, 단위 296개·모바일/PC E2E 200개가 통과했으며 이번 수동 관리에서도 해당 회귀 검사를 유지했습니다.

## 교배·산란·부화

- **12~59턴 성체**가 신규 교배할 수 있습니다. 근친·Lilly × Lilly·잠정 복합 조합은 공개 정보 기반 경고 확인 후 허용합니다. 일반 성별·성체·회복·은퇴·슬롯 조건은 유지합니다.
- 교배 성공 시 부모 스냅샷과 시즌의 자손 유전형·다유전자 값·성별·고유 외형 시드를 결정적으로 저장합니다. 부모의 외형 시드를 복사하지 않습니다.
- 교배 **+2턴에 정확히 2알을 한 번만 산란**합니다. 추가 산란은 없습니다.
- 교배 시작 시 인큐베이터 빈 슬롯 **2칸**을 예약합니다. 빈 슬롯 0·1칸에서는 실행을 차단하고 부족한 수를 표시합니다. 산란 시 수거 대기 알 2개의 예약으로 전환하고 산란 일정을 종료합니다. 컬렉션 암컷 이미지의 두 알을 한 번 누르면 두 슬롯에 배치됩니다. 다른 교배나 구매는 예약 공간을 사용할 수 없습니다.
- 산란 후 4턴 휴식: 교배 **+6턴부터** 다시 교배할 수 있습니다.
- 모든 신규 알은 **수거 후 정확히 4턴**에 판정합니다. 수거 전에는 부화가 진행되지 않습니다. 기본 무정란은 알마다 독립적으로 5%, 생존 가능한 수정란의 기본 부화 성공률은 95%입니다(기본 전체 알 기준 90.25%). 비생존 유전형과 별도의 게임 전용 열성 건강 변이가 실제 결과에 추가로 반영됩니다.
- 부화한 새끼와 무정란·실패 알은 슬롯에 남습니다. 새끼를 눌러 컬렉션에 수령하고, 실패 알은 눌러 제거합니다. 처리 전에는 슬롯을 계속 차지합니다.
- 부화 시 기존에 확정한 유전형을 그대로 상속합니다. 무정란·실패 알은 개체나 보상으로 등록하지 않고 유전 관찰 증거에서 제외합니다.
- 60턴에 은퇴해도 이미 시작한 산란 시즌은 생존하는 동안 완료합니다. 산란 전 암컷 사망 시 남은 산란만 취소하고 기존 알은 계속 판정합니다.
- 산란 즉시 수거하면 교배 +6턴 부화, +18턴 성체입니다. 늦게 수거하면 실제 부화일부터 12턴에 성체가 됩니다. 부화한 자손의 이름·급여·성장·다음 세대 교배·영구 혈통 조회가 가능합니다.

## 노령·은퇴·수명

나이는 `현재 턴 − 부화 턴`입니다. 50턴부터 노령, 60턴부터 신규 번식 은퇴입니다.

| 도달 나이 | 해당 턴 자연사 확률 |
| --- | --- |
| 0~64턴 | 0% |
| 65~69턴 | 1% |
| 70~74턴 | 3% |
| 75~79턴 | 8% |
| 80~84턴 | 18% |
| 85~89턴 | 40% |
| 90턴 이상 | 100% |

성체 그래픽은 노령에도 그대로 사용합니다. 무작위 질병·돌연사는 없습니다. 자연사는 개체 ID·게임 시드·해당 나이로 재현하며, 처리 턴을 저장해 급여·자연사 중복 처리를 막습니다. 사망 개체는 보유 공간에서 제외하고 혈통·부모·자손·유전형·표현형·번식 기록을 유지합니다. 자연사 확률과 수명은 게임 규칙입니다.

## 저장 v11·새 게임

IndexedDB `active`와 JSON 백업은 **저장 v11 / 외형 regional-2**를 사용합니다. 모든 새 개체·상점 부모·배아는 실제 유전체와 고유 외형 시드·버전을 기록합니다. 저장 후 재접속해도 동일한 외형을 재현하며 저장 완료 전 행동을 화면에 반영하지 않습니다.

**이전 v2~v10 저장은 자동 이전하거나 삭제하지 않습니다.** 기존 슬롯을 그대로 두고 새 게임 시작이 필요하다고 안내합니다. 설정에서 명시적으로 새 게임을 확정하면 같은 IndexedDB 트랜잭션으로 이전 원본을 아카이브에 남기고 새 게임을 저장합니다. 현재 버전 백업만 복원할 수 있으며 이전 원본은 아카이브 JSON으로 내려받을 수 있습니다. 이전 게임 규칙·마이그레이션 검증 함수는 역사 회귀용으로 보존하지만 정식 저장 진입점은 호출하지 않습니다.

기존 7일 턴·12턴 성체·급여·교배 1회 2알·슬롯 예약·수거 후 4턴 부화·수동 수령·수명·크레 러시 급여 규칙은 유지합니다. [정식 통합 계약·측정 기준·검증·제한](docs/regional-engine.md).

## 구조·유전학과 아트 한계

- `src/game/hardcore/lifecycle.ts`: 고정 규칙·나이·자동 급여·노령 확률.
- `season.ts`, `offspring.ts`: 수정 시 자손 확정·산란 시즌·알 판정·공통 유전 어댑터.
- `calendar.ts`, `time-source.ts`: 7일 턴 처리와 보존된 이전 시간 어댑터.
- `migrate-lifecycle.ts`, `migrate-single-clutch.ts`, `migrate-album.ts`, `migrate-risk.ts`, `save.ts`, `validation.ts`, `src/storage/hardcore.ts`: 역사 회귀 검증·v11 무결성·원자적 저장.
- `src/genetics/advanced`: 기존 멘델·보인자 추론·게임용 60개 가상 좌위. 멘델·60좌위 상속 확률은 유지하며, 외형·명칭·가격·도전은 정식 regional-2 관찰 경로를 사용합니다.

Lilly White·동일 라인 Axanthic과 잠정 복합 좌위의 근거/한계, 공개 지식 기반 가격·예측, 별도 가족의 주변확률 근사도 기존과 같습니다. 가상 외형 좌위·성별 50:50·급여·일정·수명은 실제 생물학의 확정 확률이 아닌 게임 모델입니다.

아트는 기존 PNG·실루엣을 사용한 명암 개선 v2의 결정적 96×96 출력입니다. 레퍼런스 원화와 같은 품질이나 포즈라고 주장하지 않습니다. [아트·눈 주변 팔레트 기록](docs/phase6.md), [홈 레퍼런스 비교](docs/reference-home.md), [이전 UI 테마 비교](docs/ui-tone.md)는 보존하며 해당 이미지는 당시 버전 캡처입니다.

```bash
node scripts/compile-gecko-art.mjs --check
npm run typecheck
npm test
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

기존 회귀 테스트는 삭제하거나 건너뛰지 않습니다. 이전 v5 규칙의 단위 검증은 명시적인 legacy fixture를 사용하며, 실제 앱의 E2E는 새 규칙에 맞춰 자동 급여·7일 턴·4턴 부화·12턴 성체를 검증합니다. v1.2 테스트에는 빈 슬롯 0·1·2개 경계·동시 교배 예약·단일 산란과 실제 구버전 진행 중 저장 이전, 12·50·60·65·90턴 경계, 독립 알 확률, 재현성·중복 방지·5세대·저장 이전/복원을 포함합니다.

최종 실행 결과와 실제 모바일 캡처는 [v1.2 검증 기록](docs/v1.2-lifecycle.md)에 기록합니다. 모바일 검증은 Chromium 터치 에뮬레이션(360×800)이며 실물 iOS/Safari 검사는 포함하지 않습니다.

## 혈통 앨범

[혈통도 구현·비교 이미지·저장·한계](docs/lineage-reference.md): 관심 혈통을 실제 시조 ID로 등록·이름 변경·해제하고, 선택 개체의 부모/조부모 7노드와 실제 후손을 탐색합니다. 시조와 후손의 같은 크기 스프라이트를 비교하며 양쪽 개체를 검색해 바꿀 수 있습니다. 판매·폐사·상점 외부 부모도 같은 기록으로 보존합니다. 컬렉션 상세에서 해당 혈통도를 바로 열고 상단 버튼으로 공통 턴을 진행합니다. 통계/유전 연구 영역은 두 개체의 외형 비교로 교체했습니다.

당시 저장 v8은 기존 혈통 이름에 `founderId`·`favorite`만 추가합니다. 이전 v7 개체·유전·알·교배·상점·가격 기록은 그대로이며, 실제 시조가 불명확한 예전 이름은 미확인으로 보존합니다. 관심 등록 해제는 기록을 삭제하지 않습니다. 360~430px에서는 페이지 세로 스크롤과 가족도 내부 가로 스크롤로 카드와 44px 터치 영역을 유지합니다.

혈통도 상단 배너를 제거하고 관심 혈통을 가로 슬라이드로 변경했습니다. 한 화면에 두 카드가 보이며 세 개 이상은 옆으로 밀어 확인합니다. 8개를 넘는 목록도 끝에서 자동으로 이어지고 개체 선택·이름 변경·등록 해제는 그대로 작동합니다.

## 위험 교배와 근교계수

[구현·검증·모바일 스크린샷](docs/breeding-risk.md): 기록된 전체 혈통의 근교계수 F를 계산하고, 근친·Lilly·복합 조합을 통합 경고 후 교배할 수 있습니다. F는 질병 확률이나 하트 벌점이 아닙니다. 숨은 새 상점 재고에는 기존 C/S/H 부모에서 상속된 매물도 등장하며 가격 공식과 최초 노멀 한 쌍은 유지합니다. 가상 열성 변이 2좌위는 실제 대립유전자 상속으로 배아 발달/번식에 영향을 줍니다. Lilly 비생존 배아는 정상 개체로 등록하지 않고 유전적 원인을 가진 실패 알로 보존하며 슬롯을 반환합니다. Cappuccino/Sable/Highway의 미검증 조합에 치사율을 만들어 넣지 않습니다.


## 교배 개체 검색

교배 팝업의 성별별 **개체 변경** 버튼으로 검색창을 엽니다. 이름·고유 번호·모프 검색과 모프/성장/교배 상태/세대/확인된 형질/공개 possible het/혈통 조건을 함께 적용하고, 교배 가능·이름·나이·세대·최근 획득·혈연 거리순으로 정렬합니다. 선택한 상대의 실제 부모 ID를 기준으로 후보마다 혈연을 표시하며, 판매·폐사한 조상도 계산에 포함합니다. 근친 관계는 선택을 제한하지 않고 기존 실행 전 위험 확인을 유지합니다.

성장 중 개체는 성별을 공개하지 않고 두 목록에 표시하며 성체 전에는 선택할 수 없습니다. 선택·해제는 해당 슬롯만 바꾸고, 취소·닫기·Escape는 기존 두 부모를 유지합니다. 후보의 교배 상태는 개체 조건과 공통 슬롯 여유를 표시하며 최종 두 부모의 조건은 기존 교배 팝업에서 다시 확인합니다. 낮은 하트는 기존 엔진이 허용하는 범위에서 관리 권장으로 표시합니다.

[구현·혈통 판정 범위·모바일 캡처·테스트](docs/parent-search.md)를 참고하세요. 검색은 공개 지식만 사용하며 숨은 보인자 대립유전자를 필터에 사용하지 않습니다. 저장 형식과 유전·근교계수·교배·턴 계산은 유지합니다. 최종 복합 모프 필터 추가 후 관련 E2E 14개도 다시 통과했습니다.

## 크레 러시 — 파충류 카페 알바

공통 상단 게임머니의 **+**에서 엽니다. 신규 v3 근무는 **6~20마리**의 업무량과 네 단계 난이도를 독립적으로 추첨합니다. 업무량은 한가한 매장 25%(6~8), 평소처럼 35%(9~12), 손님이 많네? 25%(13~16), 퇴근 좀 하자! 15%(17~20)이며 구간 안에서는 균등 추첨합니다. 초반 한 마리부터 최대 세 마리가 독립적으로 돌진합니다. **근무가 끝날 때까지 총량·남은 시간·전체 진행률을 숨깁니다.** 현재 웨이브·처리 수·일당만 보이고, 마지막 판정 뒤 퇴근과 실제 업무량을 공개합니다.

급여는 **max(0, 기본급 10,320원 + PERFECT×1,000원 + GOOD×500원 − MISS×1,500원)**입니다. 별도 업무량 수당은 없으며 전원 PERFECT이면 6마리 16,320원 / 10마리 20,320원 / 20마리 30,320원입니다. **급여 받기**로 기존 게임머니에 한 번 지급합니다. 다음 턴에 새 알바가 열리며 게임 턴과 유전·브리딩 RNG는 알바로 진행되지 않습니다. [규칙·추첨 검증·모바일 화면·성능 재측정](docs/rush-secret-shifts.md)에 현재 구현을 기록합니다.

검증: 타입·빌드·아트 해시, 단위 296개 통과. 100만 회 추첨 및 신규 모바일/PC 8개 시나리오 재검증 통과. 전체 E2E 194개에서 발견한 결과 화면 가림 한 건의 수정·재검증 내역도 문서에 기록했습니다. 20마리 근무/CPU 지연 4배에서 보유 6마리·300마리의 프레임 P95는 각각 16.7ms·16.8ms이며 기존 10마리 근무와 같았습니다.

닫기·백그라운드·새로고침 후 이어하기와 미수령 급여 복원을 지원합니다. 저장 v9 이후의 선택적 `cafeRush` 버전 1·2·3, 기존 IndexedDB의 진행/수령 기록, 같은 트랜잭션의 화폐·수령 확정으로 중복 지급과 이전 백업 재실행을 방지합니다. v3의 난이도·업무량·마릿수·전체 웨이브는 시작 시 확정해 저장합니다. **기존 v1·v2는 원래 10마리·25초·최대 3,000원 급여를 유지**하며 미수령/수령 기록을 새 공식으로 재계산하지 않습니다. 복원 자금은 백업 금액을 그대로 사용하며 이미 받은 급여를 다시 더하지 않습니다. 같은 게임 ID·시드의 이 기기 기록을 보존하므로 같은 시드로 새 게임을 만들어도 알바 이력은 유지됩니다. 새 시드는 별도 게임입니다.

[플레이 감각 개선·전후 화면·저장 호환·한계](docs/cre-rush-polish.md)는 v2 구현 기록입니다. 짧은 비행 호·뱅킹·세 가지 픽셀 자세, 시드별 배치 변화, 즉각 접촉 반응, PERFECT/GOOD 차등 연출, 실패 이유, 연속 포획과 결과 기록은 v3에서도 유지합니다. 선택 진동은 기본 꺼짐입니다. 기존 보유 개체의 PNG·마스크·렌더링과 유전 모델은 유지합니다. 최초 구현 기록은 [v1 문서](docs/cre-rush.md)에 있습니다.

개체 수 증가에 따른 돌진 끊김은 [성능 조사·전후 측정](docs/rush-performance.md)에 기록했습니다. 진행 검증·자동 저장은 전용 Worker에서 처리하고, 모달 뒤 화면은 마운트와 선택 상태를 유지하며 갱신을 멈춥니다. 이 최적화는 v3에서도 유지합니다. 재측정은 `scripts/benchmark-rush.mjs`로 실행하며 기본은 기존 v2 비교, `PERF_TARGETS=20`은 같은 v3 20마리 근무를 보유 수별로 비교합니다.

## 첫 게코를 기다리는 플레이

보유 개체가 0마리인 컬렉션은 **첫 게코를 기다리는 시간** 패널을 표시합니다. **카페 알바하기**는 상단 +와 같은 크레 러시 진행 상태를 열고, **상점 구경하기**는 현재 매물을 유지한 채 상점 탭으로 이동합니다. 구매하면 패널이 사라지고, 판매·폐사로 보유 수가 다시 0이 되면 나타납니다. 필터 결과만 빈 경우에는 기존 필터 안내를 유지합니다. 첫 구매 플래그나 새로운 게임 상태는 추가하지 않았습니다. [모바일 캡처·변경 범위·검증](docs/empty-collection.md)을 참고하세요.

검증: 타입 검사·빌드, 단위 277개·전체 모바일/PC E2E 180개 통과. 예비 브리더 안내 관련 8개 시나리오에서 진행 공유·급여 1회·구매/판매/폐사·저장 복원·320~430px 배치를 확인했습니다.


### 브리딩 도전

혈통도 상단에서 5개 목표 중 하나를 선택하고 실제 해칭으로 도전합니다. 목표 변경은 10턴 제한이며 최초 달성 시 즉시 해제됩니다. 수동 새끼 수령과 별도로 실제 부화 턴에 기록하고, 최초 외형/혈통과 보상·미확인 축하 화면을 저장합니다. 컬렉션 칭호는 서로 다른 목표의 완료 수(0~5개)에 따라 견습 브리더부터 전설의 브리더까지 자동 승급합니다. 완료한 서로 다른 도전 1개마다 매 턴 1마리분의 사료가 자동 면제됩니다. **필요 사료 = max(0, 생존 보유 수 − 완료 수)**이며 별도 슬롯 배정은 없습니다. 무료 급여도 하트를 회복하고, 부족 경고는 면제 후 수량을 사용합니다. 새 해칭 보상은 다음 턴 급여부터 적용합니다. [실제 급여 면제·저장 호환·검증](docs/challenge-feeding.md).

현재 유전·외형 엔진을 읽는 임시 판정이며 팬텀 유전자나 실제 전신 품질을 검증하지 않습니다. [목표별 기준·보상 적용 범위·저장 호환성](docs/breeding-challenges.md)을 확인하세요.

칭호의 단계·구세이브 호환·모바일 검증은 [자동 브리더 칭호](docs/breeder-rank.md)에 정리했습니다.

선택한 도전 옆과 **전체 도전 목표 팝업의 각 목표 카드**에는 현재 게임 렌더러로 그린 대표 외형을 표시합니다. 별도 일러스트나 저장 개체를 만들지 않고 고정된 합법 유전체를 기존 외형 어댑터에 연결합니다. 실제 성공 판정·잠금·보상은 기존 부화 이벤트가 담당합니다. [목표별 외형 설정·캐시·모바일 검증](docs/challenge-previews.md).

### 정식 외형 엔진 regional-2

모든 컬렉션·상점·부모·교배·부화·혈통·도전 이미지는 **`src/engine/render.ts` → `src/engine/regional/render.ts` → `lighting.ts`**를 사용합니다. 명암 개선 실험본 v2의 100개 고정 출력과 픽셀이 일치하며 v1 마감·구형 스프라이트 렌더러·비교 전환 코드는 제거했습니다.

최종 피부 재질과 픽셀에서 면적·밝기·실제 반점·선 연결을 관찰해 한국어 이름·가격·도전 판정에 함께 사용합니다. 시장 기준가·가중치·수수료·반올림은 유지합니다. C/S/H 복합 및 동형접합은 기존 상속 규칙 위의 잠정 시각 모델이며 새 치사율을 추가하지 않습니다. [구현·수치 정의·전체 검증·성능·제한](docs/regional-engine.md). 기존 실험 비교 PNG와 [관찰 근거](docs/appearance-prototype.md)는 역사 자료입니다.

정식 v2 통합 검증(2026-10-17): 타입·빌드·아트 해시·전체 단위 **382개** 통과. 모바일/PC 274개 시나리오 실행에서 발견한 실패 12개를 수정한 뒤 관련 14개 재검증도 모두 통과했습니다. [실행별 결과·현재 CI·브라우저 캡처·성능](docs/regional-engine.md). CPU 4배 제한/20마리 근무에서 보유 6마리와 300마리의 프레임 P95는 모두 16.8ms였습니다.
