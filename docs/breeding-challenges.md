# 브리딩 도전 (임시 판정 v1)

혈통도 상단 두 관심 혈통 영역을 하나의 도전 패널로 교체한다. 기존 `individuals`와 `lineages`는 보존하고 가족·후손 탐색, 선택 개체, 세대 비교를 그대로 사용한다. 이전 관심 가문의 등록/이름 변경/해제 엔진도 보존한다. 이번 화면에서 등록 UI만 제거한다.

## 플레이와 기록

- 다섯 목표를 처음부터 공개한다. 목표 선택 시 현재 턴 +10까지 변경할 수 없다. 같은 목표를 다시 선택해도 기간이 늘지 않는다. 만료되어도 목표는 유지된다.
- `seasonEvents`의 성공적인 `incubating → hatched` 전환에서만 평가한다. 수거 대기, 실패/무정란, 구매, 과거 개체 조회, 새끼 수령은 평가하지 않는다. 선택 전 교배한 알도 선택 후 부화하면 인정한다.
- 달성은 목표별 한 번. 두 알의 동시 부화와 동일 턴 재처리에도 한 기록/한 보상만 남는다. 즉시 변경 잠금을 해제하되 다음 목표를 자동으로 고르지 않는다.
- 기존 수동 새끼 수령 흐름을 유지한다. 새끼가 아직 컬렉션에 없어도 실제 부화 턴에 성공 팝업을 띄운다. 미확인 팝업은 재접속 후에도 복구하며 확인도 자동 저장한다.
- 최초 개체의 부화 당시 전체 스냅샷(외형 버전/고정 시드/유전체/잠재 형질/부모 ID/혈통 ID), 당시 표시 모프·상세 표현형·알 ID·달성 턴을 보관한다. 이후 이름 변경·분양·폐사로 바뀌지 않는다. 컬렉션 수나 사료 수요에는 추가하지 않는다.

## 임시 판정과 한계

실제 브리더 업계의 표준 수치가 아닌 **현재 게임 엔진용 목표**다. `challenge-evaluator.ts`만 기존 유전·외형 데이터를 읽는다. 유전자 전달, 렌더링, 난수, 이름, 경제 가중치는 변경하지 않는다. `patterns-1`에서 계산 가능한 특성만 인정하며, `legacy-1`/`5.0` 외형은 정밀 관찰 데이터가 없어 성공으로 추정하지 않는다.

| 목표 | 임시 기준 |
| --- | --- |
| 칠흑의 완성 | 실제 팔레트 분류 다크, 베이스 RGB의 가중 명도 ≤58, 실제 무늬 계획의 기본색 면적 ≥72%, Lilly/아잔틱 제외 |
| 타오르는 태양 | 오렌지 분류, 오렌지 발현 점수 ≥0.75, 기본색 면적 ≥70%, 실제 반점 ≤5개, Lilly/아잔틱 제외 |
| 별이 내린 밤 | 실제 서로 분리된 반점 ≥65개, 머리·몸통·꼬리에 각각 ≥3개. 요청 반점 수만으로 인정하지 않음 |
| 순백의 계승자 | Lilly 발현, 크림 발현 ≥0.90, 실제 무늬 계획의 크림 면적 ≥48% |
| 흑백의 걸작 | 위 고피복 Lilly 조건과 실제 아잔틱 발현(ax/ax) 동시 충족 |

면적은 96×96 옆모습 계획의 도색 가능한 피부 기준이다. 전신/반대편까지 보장하는 비율이 아니다. 팬텀 좌위/발현 모델이 없어 검증하지 않으며 블랙 목표는 어두운 체색의 대리 지표다. 솔리드는 무늬가 적은 강한 오렌지의 근사이며 음영까지 단색이라는 뜻이 아니다. 흰색도 실제 백색/크림 표현 구분이나 생체 색소 측정이 아니다. 점 분포는 세 부위 존재 조건이며 실제 전신 균형을 평가하지 않는다. 숨은 보인자는 화면에 공개하지 않는다.

다섯 기준 모두 **합법적인 현재 가상 대립유전자**로 구성한 테스트 부모에서 기존 상속/수정/부화 엔진을 통해 달성 가능함을 검증했다. 게임 매물이나 자손을 목표에 맞춰 조작하지 않는다. 극단적 수치의 실제 선택교배 소요 기간과 현 세이브 집단의 대립유전자 가용성은 보장하지 않는다. 팬텀을 가진 실제 극흑 개체, 완전 솔리드, 반대편 포함 전신 품질은 현 엔진으로 검증 불가능하다.

## 보상

도전당 `reward: {feedExemptionSlots: 1, titleId}`를 완료 기록에 최초 한 번만 저장한다. 보유 보상은 완료 기록에서 집계하여 별도 카운터 불일치를 방지한다.

기존 먹이 면제/업적/칭호 엔진은 없었다. 따라서 **먹이 면제 슬롯은 실제 획득 기록으로 적립만 하며 현재 사료 소비를 줄이지 않는다.** UI에서도 이를 명시한다. 기존 모든 생존 보유 개체당 1턴 1개 자동 급여 규칙을 보존했다. 향후 면제 정책이 정의되면 `challengeFeedSlots`를 연결할 수 있다.

칭호는 도전별로 해금한다. 전체 목표 팝업에서 착용/해제하면 컬렉션 기존 대표 패널 위에 작은 칭호를 표시한다. 신규 달성은 착용값을 변경하지 않는다. 카드·메인 패널 크기는 바꾸지 않는다. 칭호는 이번 게임의 보상 이름이며 실제 브리더 모프명으로 쓰지 않는다.

## 저장 및 향후 엔진 연결

저장 v10의 선택 확장 `breedingChallenges.version: 1`을 사용한다. 필드가 없는 구세이브는 미선택/완료 0개/칭호 미착용으로 읽으며 원본 유전·경제 데이터에 기본값을 쓰지 않는다. 기존 v2~v9 이전 경로도 유지한다. 확장 필드/중복 보상/잠금/달성 알·스냅샷 일치 여부를 검증하며 손상 시 기존 복구 흐름에서 오류를 표시한다. 동일 IndexedDB 저장, Worker, JSON 백업과 복원을 사용한다.

향후 유전 개편 시 `challenge-evaluator.ts`와 `challenge-rules.ts`의 임계값/지원 버전을 교체하면 된다. 과거 달성을 새 판정식으로 재계산하지 않는다. 새로운 최초 달성 기록에 다른 평가 버전이 필요하면 완료 타입·검증기를 명시적으로 확장한다.

## 검증

- 전체 단위 테스트: **337개 / 29개 파일 통과**. 다섯 목표의 실제 상속·부화와 게임 상태 무변경 비교, 잠금, 과거/구매 제외, 중복 보상, 최초 기록 보존, 구세이브/손상 검증을 포함한다.
- 관련 모바일·PC E2E: **64개 통과 (3.0분)**. 도전, 혈통, 수동 산란/수령, 성장 크기, 부모 조회, 컬렉션 관리자, 공통 UI와 기존 실제 게임 플레이를 검사했다. 전체 E2E를 반복하지 않고 변경 경로를 중심으로 실행했다.
- TypeScript 검사, 프로덕션 빌드, 기존 PNG/런타임 해시 일치 통과.
- 모바일 **360~430px**, 목표 선택/10턴 만료/달성 전후 새로고침/팝업 복원/직접 칭호 착용을 Chromium 터치 환경에서 확인했다. 실제 스마트폰 하드웨어 검사는 수행하지 않았다.
- 캡처: [선택 개체와 혈통 390px](breeding-challenges/lineage-family-390.png), [혈통 화면 360px](breeding-challenges/lineage-360.png), [목표 목록 390px](breeding-challenges/goals-390.png), [실제 부화 성공 390px](breeding-challenges/success-390.png).

UI가 제거된 관심 혈통 등록/슬라이드 E2E는 UI 제거·기존 메타데이터 보존·도전 목표 접근 검사로 교체한다. 기존 엔진의 관심 혈통 단위 테스트는 유지한다.

마지막 저장 검증의 손상 배열 처리 보강 및 수거 전 장기 대기 검사 추가 후 도전 단위 테스트 11개·모바일/PC 도전 E2E 6개·타입 검사·프로덕션 빌드를 재검증했다.
