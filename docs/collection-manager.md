# 6마리 컬렉션과 전체 개체 관리

2026-10-16. 기존 카드·게임 행동·저장 모델을 재사용한 컬렉션 UI 변경입니다.

## 메인 화면

- 실제 보유 개체 수는 전체 수량을 표시하고, 현재 모프/성장 필터와 정렬 결과의 앞 **최대 6마리**만 3열×2행에 표시합니다. 추가 카드·더 보기·2열 전환은 없습니다.
- 기존 **기본순 오른쪽 격자 버튼**으로 `전체 개체`를 엽니다. 기존 컨디션 창의 목록 바로가기도 같은 팝업을 사용합니다.
- 공통 헤더·턴 버튼·내비게이션의 CSS와 렌더링 위치는 바꾸지 않습니다. 모바일 컬렉션 중앙 행만 실제 가용 높이에 맞춰 대표 패널과 두 카드 행을 배분합니다. 작은 화면에서는 간격·여백과 정보 행 높이를 조절하고, 이미지의 정사각 비율과 기존 성장 배율을 유지합니다.
- 개체 0마리의 예비 브리더 패널과 1~5마리의 실제 카드 수, 필터 결과만 빈 경우의 안내를 유지합니다. 대표 패널의 화살표로는 전체 보유 개체를 계속 둘러볼 수 있습니다.

## 지속형 관리 팝업

전체 개체 팝업은 세로 스크롤하는 **3열 격자**이며 메인과 같은 `CollectionCard`를 사용합니다. 카드에는 실제 외형·성별 공개 상태·이름·모프·세대·현재 상태와 기존 가격 함수의 분양 예상가를 표시합니다.

카드의 선택 버튼은 고유 ID만 선택하며 팝업을 닫지 않습니다. 상단 선택 개체 관리 영역에서 상태/하트/나이/모프를 확인하고 **상세·분양** 또는 **교배**를 이용합니다. 카드의 기존 더보기·상태 바로가기·알 쌍 수거도 유지합니다. 이름·ID 검색, 모프/패턴 필터, 정렬 및 접을 수 있는 성장·공개 성별 조건을 제공합니다. 모프·정렬·성장 조건은 메인에도 반영하며 숨은 유전형은 검색하지 않습니다.

기존 `Details`, `Breeding`, `ResourceManagement`, `EndTurnButton`을 사용합니다. 별도의 구매/급여/분양/교배 엔진을 만들지 않았습니다.

- 상세에서 이름을 저장하거나 분양하고 창을 닫으면 관리자에 남습니다. 분양된 개체만 목록에서 빠지며 혈통·유전 원본은 기존 판매 기록으로 유지합니다.
- 사료·사육장 관리는 기존 팝업을 위에 열고, 닫으면 같은 선택·필터·스크롤 위치로 돌아옵니다.
- v1.2 급여는 기존 **턴 종료 자동 급여**입니다. 팝업에 사료 재고와 다음 턴 급여 수를 표시하고, 기존 턴 버튼으로 급여/성장/휴식을 함께 진행합니다. 사료 부족 경고·취소·사료 구입도 기존 UI를 사용합니다. 이전 수동 급여 규칙의 저장에는 기존 `feed` 행동을 제공합니다.
- 교배 취소와 실행 후에도 관리자를 유지합니다. 일반 컬렉션의 기존 교배 성공→인큐베이터 이동은 그대로 두고, 관리자가 열린 경우에만 컬렉션에 남습니다.
- 상세의 영구 혈통 기록은 같은 `Lineage`를 추가 대화상자에서 보여줍니다. 기록 창을 닫으면 관리자로 돌아오며 혈통 탭 자체는 변경하지 않습니다.
- 네이티브 모달을 겹쳐 기존 포커스/닫기 처리를 사용합니다. 닫기 또는 Escape 전까지 전체 개체 관리자는 마운트 상태를 유지합니다. 단순 선택·관리 창 열기/닫기는 게임 저장을 쓰지 않습니다.

팝업의 열림·선택·스크롤은 UI 상태입니다. 새로고침하면 메인으로 돌아오며, 기존 IndexedDB에 저장한 실제 개체·판매·급여·턴·교배 상태는 유지합니다.

## 대량 개체

전체 배열은 기존 `owned`/`collectionEntries`에서 조회합니다. 목록 DOM과 Canvas는 현재 화면과 앞뒤 두 행만 유지하는 창 방식으로 제한합니다. 개체를 전부 DOM에 추가하는 무한 누적 방식은 사용하지 않습니다.

행 높이와 3열 구조를 기준으로 전체 스크롤 공간을 확보하고 `ResizeObserver`로 실제 카드 피치와 가용 높이를 측정합니다. 스크롤 이벤트는 프레임당 한 번만 반영합니다. 공유 카드는 `memo`, 각 개체 스프라이트는 `useMemo`를 사용하며 선택 변경은 다른 카드의 이미지를 다시 그리지 않습니다. 유전체·표현형·가격 캐시는 기존 구현을 사용합니다.

기존 `referenceHomeGame`의 6종 유전 기록을 기반으로 고유 ID·외형 시드·나이/성장 단계를 부여한 검증용 300마리 게임으로 맨 처음·중간·끝의 카드 접근, 카드 DOM 상한 30개, 목록 선택 시 Canvas 재그리기 0회, 사육장 창 복귀 시 스크롤 유지와 저장 불변성을 검사합니다. 최종 측정 파일은 [모바일](collection-manager/performance-mobile-chromium.json)·[PC](collection-manager/performance-desktop-chromium.json)에 기록합니다. `openMs`는 Playwright 터치/클릭부터 대화상자 확인까지이며 자동화 왕복 시간을 포함합니다.

## 화면 검증과 캡처

Chromium 모바일 터치/PC 브라우저를 사용합니다. 실제 Android 기기 측정은 아닙니다.

- 0·6·7·37마리 각각 360×640, 360×800, 390×693, 390×844, 412×760, 430×932에서 메인 콘텐츠 높이=가용 높이, 가로 넘침 없음, 6개 이하의 카드와 CTA/하단 메뉴 접근을 검사합니다.
- 실제 44px 상단·34px 하단·20px 좌우 안전 여백을 적용한 일반 세로 화면에서도 메인의 스크롤과 하트 패널 위치를 검사합니다.
- 공통 UI의 기존 전 탭 좌표·크기 비교, 성장 50/75/100% 배율·중심·원본 픽셀, 상태 클릭과 남은 턴 2→1→완료, 저장 복원을 유지합니다.
- 전체 개체의 독립적인 실제 터치 스크롤, 마지막 개체 접근, 가격 정렬·필터·검색, 미성체 성별 비공개, 선택 유지·다른 창 복귀·실제 판매·급여·교배를 확인합니다.

PC는 기존 큰 대표 패널·카드의 비율과 중앙 스크롤을 유지합니다. 물리적으로 매우 짧거나 가로인 모바일 화면도 중앙 스크롤을 유지합니다. 관리 팝업도 가로의 짧은 화면에서는 전체 팝업 스크롤로 컨트롤에 접근하며 숨김으로 콘텐츠를 잘라 맞추지 않습니다.

## 검증 결과

- 타입 검사·프로덕션 빌드·아트 PNG/런타임 해시 통과.

- `public/sw.js`: 오프라인 셸 캐시 버전 30.

`src/game`, `src/genetics`, `src/engine`, `src/storage`, `src/hooks`의 게임 규칙·저장/불러오기·유전·가격·성장 코드는 변경하지 않았습니다.
