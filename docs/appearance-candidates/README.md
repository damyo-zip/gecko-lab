# 원화 보존 외형 후보 A/B/C

비교 화면: **`/lab/appearance/candidates`**. 기존 `/lab/appearance` 상단에서도 이동할 수 있습니다.

게임의 정식 렌더러는 작업 시작 시점의 **regional-2** 그대로입니다. 후보를 자동 선택하거나 게임에 적용하는 기능은 없습니다. 엔진·유전·가격·도전·저장·성장 코드와 원본 PNG는 수정하지 않았습니다.

## 비교 조건

왼쪽부터 이전 정식 → 현재 v2 → A → B → C입니다. 각 행의 유전체 60좌위, 외형 시드, 파이어 상태를 다섯 렌더러에 동일하게 전달합니다. 개체별 시드를 바꿔 예쁜 결과만 골라내지 않습니다.

이전 정식은 통합 직전 커밋 **c934363f854b47c154d8d8127d6d23abbe692e9e**의 PNG/patterns-1 렌더러와 연결 방식을 복원했습니다. 해당 Git 커밋을 별도 임시 폴더에 추출해 **당시 adapter와 renderSprite를 실제 실행한 60개 출력**을 `tests/fixtures/authored-c934363-hashes.json`에 고정했습니다. 복원본의 출력이 모두 일치합니다. 현재 v2의 기존 100개 고정 출력도 그대로 유지됩니다.

| 후보 | 보존과 보강 범위 | 판단할 점 |
|---|---|---|
| A · 최소 수정 | 기존 무늬·피복 유지. 강한 릴리의 얼굴 일부, 작은 꼬리 표식, 제한적인 등/크라운 보강 | 원래 개체의 인상을 가장 많이 남깁니다. 모프 차이는 상대적으로 작습니다. |
| B · 균형 보강 | 릴리 저~고발현 피복, 얼굴 백색, 유전된 아잔틱 명도, 꼬리 기부/끝, 등 확장과 측면 감소, 세이블 대비 | 원화 보존과 모프 식별성을 함께 비교할 출발점입니다. |
| C · 확장 보강 | 고발현 릴리는 코까지, 더 넓은 등 패턴과 측면 감소, 큰 꼬리 표식, 넓은 밝은 군집 | 표현 차이가 가장 큽니다. 흰 부위가 넓어진 개체의 매력은 직접 확인해야 합니다. |

**세 후보의 노멀은 이전 정식과 픽셀까지 같습니다.** 숨은 아잔틱 보인자도 모습을 바꾸지 않습니다. 일반 명도의 아잔틱은 A/B/C의 결과가 같을 수 있습니다. 이 후보들의 아잔틱 차이는 주로 `어두운 명도` / `밝은 명도`에서 확인할 수 있습니다.

현재 시각 검토에서는 B가 절충안을 비교하기에 유용했습니다. 이것은 추천 출발점이며, 최종 채택 결정이나 객관적인 미적 평가 점수는 아닙니다.

## 구현 방식과 발견한 문제

v2는 재질과 부위 조명으로 원화의 색을 재구성합니다. 이번 후보는 그 조명 단계를 가져오지 않고, **이전 정식의 PNG 픽셀별 명암·무늬 합성**에서 시작합니다. 모프가 필요한 부위의 재질만 바꾸고 원화의 밝고 어두운 픽셀 군집을 재사용합니다. 이웃 픽셀 평균, 블러, 알파 색 덮기, 전체 이미지 회색 필터는 사용하지 않습니다.

- 릴리: 같은 유전체의 크림·등·측면·할리퀸 수치로 얼굴 확장과 몸통 피복을 조절합니다. B/C는 기존의 고정된 높은 피복 바닥값을 사용하지 않습니다. 고발현에서도 눈·콧구멍·입선은 원래 픽셀을 그대로 복원합니다.
- 아잔틱: 기본·암색·밝은 무늬를 별도 중성 재질로 다루고, 유전 명도를 후보별 범위로 반영합니다. 원래 위치의 명암과 홍채는 보존합니다.
- 카푸치노: 원래 팔레트를 갈색 방향으로 조정하고 꼬리 기부의 밝은 영역과 끝의 어두운 영역을 강도별로 확장합니다.
- 하이웨이: 등 경계에서 안쪽으로 밝은 재질을 확장하고 측면 패턴 일부를 줄입니다. 최초 구현에서 상위 측면 레이어가 등 보강을 가리던 문제를 수정했습니다.
- 세이블: 원래 무늬 기하를 유지하면서 기본 체색을 어둡게 하고, 고정 시드의 머리·등 군집을 밝게 보강합니다.

시각 검토와 경계 검사에서 **밝은 재질을 RGB 254 부근에서 시작하면 원화의 밝은 픽셀 여러 단계가 같은 흰색으로 뭉치는 문제**를 발견했습니다. 백색 중간톤을 낮추고 하이라이트 여유를 확보해 해결했습니다. 단순히 전체 대비나 검은 윤곽을 강화한 것이 아닙니다.

모프 간 보강 순서는 꼬리 → 등 → 세이블 군집 → 릴리 백색입니다. 이번 후보의 상세 비교·검증·미적 검토 범위는 요청한 단일 모프 여섯 종류이며, 복합 모프 전반의 미적 검토는 후속 작업입니다. 실제 유전 방식이 불확실한 부위별 강도와 재질 계수는 **게임용 시각 모델**이며, 새 유전 법칙이나 생존 확률을 정의하지 않습니다.

## 검증

- 전체 단위 테스트 391개 및 타입 검사·프로덕션 빌드 실행. 최초 검사에서 발견한 백색 명암 손실은 수정 후 관련 25개 검사로 재확인했습니다.
- 관련 브라우저 검사 26개: 새 비교 화면, 기존 v2 연구실, 기존 스프라이트 연구실의 모바일/데스크톱 검증. 최초 테스트의 스크롤 위치 가정을 수정한 뒤 실패한 두 경우도 재검증했습니다.
- 노멀: 5개 유전 배경 × 2개 파이어 × 12개 시드에서 이전 정식과 정확히 일치. 보인자도 동일합니다.
- 6모프 × 저/일반/고발현 × 2개 파이어 × A/B/C에서 실루엣 알파·눈·입·콧구멍·윤곽 픽셀이 이전 정식과 일치합니다.
- 각 후보의 각 모프에서 12개 시드가 모두 다른 무늬를 만들고 JSON 복원 후 그대로 재현됩니다.
- 실제 브라우저의 30개 원본·30개 확대 Canvas가 Node 렌더링 픽셀과 일치합니다. 최근접 확대와 보간 비활성화도 확인했습니다.
- 360/390/430px에서 페이지 가로 넘침이 없고, 모바일 에뮬레이터에서 손가락 슬라이드 이벤트로 표가 이동하는 것을 확인했습니다.
- 비교 화면은 IndexedDB를 열거나 local/session storage에 쓰지 않습니다. 게임의 기존 이미지·모프명·가격·도전 결과·저장 내용은 후보 렌더링 전후 동일합니다. 정식 모듈에서 실험 코드를 import하지 못하게 검사합니다.
- `node scripts/compile-gecko-art.mjs --check` 통과. 원화 PNG/마스크는 변경하지 않았습니다.

구조 경계 방향과 국소 대비 진단은 [measurements.json](measurements.json)에 있습니다. 기존 대비가 10 이상인 인접 픽셀 쌍의 방향을 비교한 보조 지표입니다. 새 패턴 경계도 영향을 주므로 이 수치를 아름다움·품질 점수로 해석하지 않습니다. 확대 이미지·얼굴·96px·테라리움 화면도 함께 검토했습니다.

비교용 픽셀 캐시는 60개로 제한하고, 확대·배경 전환은 같은 결과를 재사용합니다. 측정 당시 Node 24 클라우드 CPU에서 30개 비교 출력은 초기 약 358ms, 캐시 약 0.54ms였습니다. Android 실기기 시간이나 프레임률 측정은 아닙니다. 물리 기기에서의 미적 선호와 장시간 성능 평가는 남아 있습니다.

## 주요 파일과 재현

- `src/lab/appearance/authored.ts`: 이전 정식 렌더러의 격리된 복원본.
- `subject.ts`: 동일 유전체를 이전 정식 그래픽 계약으로 변환.
- `policies.ts`: A/B/C의 보강 범위와 강도.
- `candidates.ts`: 원화 명암을 사용하는 부위별 보강과 제한된 캐시.
- `src/components/appearance-candidate-lab.tsx` / `.module.css`: 비교 UI.
- `src/app/lab/appearance/candidates/page.tsx`: 실험 전용 경로.
- `tests/appearance-candidates.test.ts`, `e2e/appearance-candidates.spec.ts`: 재현성·경계·분리·모바일 검증.

```sh
node scripts/appearance-candidates-report.mjs
npm run typecheck
npm test
npm run build
npm run test:e2e -- e2e/appearance-candidates.spec.ts e2e/appearance-prototype.spec.ts e2e/sprite-lab.spec.ts
```

과거 출력의 golden 파일은 lab 복원본으로 재생성하지 않습니다. 갱신이 필요하면 기록된 Git 커밋에서 당시 adapter/renderer를 직접 실행해야 합니다.

이번 작업은 미병합 v2 통합 브랜치를 기준으로 한 별도 후보 비교 변경입니다. 원래 통합 PR과 자동 병합하지 않으며, 후보 채택은 시각 검토 이후의 별도 작업입니다.
