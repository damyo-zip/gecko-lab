# 보유 개체 카드 이미지 확대

변경은 `collection-browser.css`의 공통 카드 Canvas 크기·위치·쌓임 순서에 한정한다. 메인 3열 목록과 전체 개체 팝업에 같은 규칙을 적용한다. 카드·텍스트·버튼의 크기/배치, 상단 대표 개체, 다른 화면의 SpriteCanvas와 성장 규칙은 유지한다.

- 390×844의 실제 성장 3단계 개체로 비교: 성체 Canvas 폭 **91~94px →119~121px**. 팝업은 **86~88px →118~120px**.
- 카드/이름 영역 좌표와 크기가 전후 동일하다. 성체의 실제 불투명 픽셀 하단은 이름 행 시작에 **3px** 겹친다. PC에서는 약 2px다.
- 이미지가 이름보다 앞에 그려지며, Gen·성별 표시를 보존한다. Canvas는 포인터 입력을 받지 않는다. 더보기·상태·알 수거를 기존 방식으로 조작한다.
- 가로 비율을 유지하며 카드 안에 수평 정렬한다. 현재 96px 스프라이트의 세로 투명 여백을 고려해 꼬리 끝을 고정하고, 짧은 화면에서는 머리가 잘리지 않도록 확대 상한을 둔다. 기존 카드의 overflow 경계를 유지해 인접 카드로 넘치지 않는다.
- 기존 성장 transform을 그대로 사용한다: 해칭 50%, 아성체 75%, 성체 100%. 추가 성장 scale이나 애니메이션이 없다. 공통 확대 프레임의 중심을 유지하며 축소한다.
- 288×288 Canvas 픽셀 원본과 `image-rendering: pixelated`/스무딩 비활성화를 유지한다. 에셋·시드·유전·외형 생성 코드와 게임 데이터/저장 구조는 변경하지 않는다.

검증: 타입 검사, 프로덕션 빌드, 기존 아트 PNG/런타임 해시 일치, 단위 **337개**, 관련 모바일·PC E2E **32개** 통과. 기존 성장/카드 관리/상태 클릭/공통 UI/수동 산란·수령 테스트를 재사용했다. 카드의 세로 중심에 대한 과거 단정만 의도된 새 프레이밍에 맞춰 바꿨으며, 성장 비율·변환 중심·가로 중심·비트맵 동일성 검사는 유지한다. 360×640부터 430×932까지의 모바일 브라우저와 PC를 확인했고 실제 스마트폰 하드웨어 검사는 수행하지 않았다.
