# 한국어 대표 모프명

2026-10-16 KST. 정식 게임의 **표시 정책만** 변경했습니다. 기존 유전 분류와 무늬 관찰, 외형 렌더링, 가격, 성장, 저장 버전은 유지합니다.

## 기존 방식과 분리

`appearanceProfile → classifyPattern`은 실제 무늬의 관찰값으로 `유전 모프 + 체색 + 기본 패턴`을 만들고 추가 특징을 별도로 계산합니다. 기존 컬렉션에는 공개 het 정보도 같은 줄에 붙었습니다. 예전 외형 버전에서는 렌더러의 6종 스타일과 유전 설명을 섞어 일부 영어 이름을 표시했습니다.

이 분류는 렌더러와 가격에도 쓰이므로 그대로 유지합니다. 그 위에 `visualName → representativeMorphName` 표시 계층을 추가했습니다. 컬렉션·전체 개체 목록·상세·교배와 후보 검색·상점과 부모·인큐베이터 부모/부화 기록·혈통 앨범은 모두 이 함수를 사용합니다. 대표명은 저장하지 않고 실제 개체의 표현된 형질에서 계산하며, 불변 개체 객체별 WeakMap으로 캐시합니다.

상세정보의 **전체 외형 분류**, **실제 무늬**, 기존 외형 수치와 공개 유전정보에는 생략된 체색·패턴·추가 특징·공개 보인 확률이 남습니다. 숨은 보인자 진실은 대표명에 사용하지 않습니다. 후보 검색은 대표명에서 빠진 공개 외형 설명도 검색하며 영어/한국어 검색을 함께 지원합니다. 복합 모프 필터는 번역된 문자열에 의존하지 않고 기존 공개 지식의 안정적인 형질 ID를 사용합니다.

**개체 고유 이름 `name`은 자동 생성 이름을 포함해 보존합니다.** 기존 `visualName`은 상점의 새 개체 저장 이름 생성에도 쓰였기 때문에, 원래 구현을 `descriptiveVisualName`으로 분리해 해당 생성 경로를 고정했습니다. 따라서 이름에 영어가 이미 들어 있어도 임의로 번역하거나 덮어쓰지 않습니다. 스크린샷의 개체 이름 `Highway 옐로 플레임 수컷`과 대표 모프 `하이웨이`는 서로 다른 필드입니다.

## 명명 규칙

전체 형질을 일괄 축약하는 우선순위 대신, **정확한 유전 모프 조합**과 **개별 모프 예외**를 적용합니다. 기존 유전 엔진이 이미 판정한 `Frappuccino`, `Luwak`, `Sorak`을 사용하며 새 유전 좌위를 만들지 않습니다.

| 실제 표현형 조건 | 대표명 |
| --- | --- |
| 릴리화이트만 발현 + 실제 트라이컬러 패턴 | 트라이컬러 릴리 |
| 릴리화이트만 발현 + 레드 체색, 트라이컬러 아님 | 레드 릴리 |
| 나머지 단독 릴리화이트 | 릴리화이트 |
| 단독 아잔틱 / 단독 하이웨이 | 아잔틱 / 하이웨이 |
| 프라푸치노 / 루왁 | 프라푸치노 / 루왁 |
| 릴리화이트 + 아잔틱 | 릴리 아잔틱 |
| 릴리화이트 + 세이블 | 릴리 세이블 |
| 릴리화이트 + 루왁 | 루왁 릴리 |
| 기존 `Sorak · 건강 위험` | 설악 · 건강 위험 |
| 단독 카푸치노·세이블·슈퍼 카푸치노·슈퍼 세이블 | 해당 한국어 명칭 |
| 알려진 단일 유전 모프 없음 | 기존 체색 + 기본 패턴 유지: 레드 플레임 등 |
| 확인한 예외에 없는 복합·새 모프 | 모든 구성 요소와 경고를 포함한 기존 설명식 명칭을 한국어로 표시 |

릴리의 트라이컬러 예외는 레드보다 먼저 적용하지만, 다른 유전 모프가 추가되면 단독 릴리 규칙을 적용하지 않습니다. 예를 들어 릴리+하이웨이를 하이웨이 하나로 축약하지 않습니다. 핀·달마시안·화이트월 등은 기존 실제 관찰에 따라 상세 특징으로 남으며 이름을 근거로 외형을 생성하지 않습니다.

요청하신 5개 예시는 각각 **레드 릴리 / 트라이컬러 릴리 / 아잔틱 / 하이웨이 / 레드 플레임**으로 검증합니다. 레드·트라이컬러 릴리의 간결한 표기는 이번 요청의 게임 표시 정책이며, 색과 패턴의 수치 경계는 기존 게임 판정 그대로입니다. 업계 공통의 절대적 품질 기준으로 주장하지 않습니다.

## 명칭 근거와 불확실한 조합

다음 국내 자료의 본문에서 표기를 확인했습니다. **명칭 사용 확인에만 이용했으며, 자료의 유전·건강·확률·가격 주장은 게임 규칙에 새로 반영하지 않았습니다.** 특히 자료별 유전 해석이나 명명 선호가 동일하지 않습니다.

자료에 쓰이지 않은 별칭을 새로 조합하지 않습니다. 예를 들어 다음은 짧은 별칭을 부여하지 않고 설명형을 유지합니다.

- `릴리화이트 + 하이웨이 옐로 플레임`
- `프라푸치노 + 아잔틱 …`처럼 확인한 대표 조합에 추가 유전 모프가 있는 경우
- `카푸치노/하이웨이 …`
- `세이블/하이웨이 · 미검증 …`, `슈퍼 하이웨이 · 미검증 …`
- 미래에 추가될 미등록 영문 모프: 알려진 부분만 번역하고 미등록 이름 자체는 보존

`display-rules.ts`의 어휘·정확한 조합·단독 명칭 표를 확장하면 됩니다. 유전 엔진을 수정하거나 저장 데이터를 이전할 필요가 없습니다. 과거 외형 버전에 실제 측정된 색/패턴 프로필이 없으면 새로운 색상 별칭을 추정하지 않습니다. `/lab`의 원본 스프라이트 프리셋과 `/lab/patterns`의 연구용 상세 분류는 원래 데이터를 유지합니다.

## 검증

- 수정 전 main `6236f70`에서 3시드 × 4개 매물 배치 × 자손/부모 12개 = **144개 실제 개체 기록**의 기준 해시를 먼저 채취했습니다. 전체 게임·JSON 백업·자동 생성된 개체 이름·렌더러 입력·RGBA 픽셀·가격이 수정 후 모두 동일합니다. 이전 실제 v7 세이브의 이전 결과/백업 해시도 동일합니다. 기준: `tests/fixtures/pre-morph-display-hashes.json`.
- 대표명 예시 5종, 정확한 복합 조합, 중복·순서 독립성, 미래 모프/미검증 조합 폴백, 경고와 het 확률 보존, 숨은 보인자가 다른 동일 외형의 검색/대표명 일치, 공개 복합 필터와 생략된 패턴 검색, 저장·복원을 검증합니다.
- 실제 브라우저에서 유전 엔진이 생성한 하이웨이 수컷을 구매하고 컬렉션·상세·부모 선택·교배·알 수거 후 인큐베이터 부모·혈통도·새로고침을 확인합니다. 캔버스 픽셀과 원래 개체/가격/저장 기록도 비교합니다. 직접 지정한 이름도 유지됩니다.
- 360×800, 390×844, 430×932 Chromium 모바일 뷰포트/터치 및 데스크톱으로 확인합니다. 실제 휴대폰 하드웨어 테스트는 수행하지 않았습니다. CSS·카드 크기·공통 레이아웃은 변경하지 않았습니다.
- 타입 검사, 프로덕션 빌드, PNG/runtime 아트 해시 통과. 전체 단위 **326개 통과**. 전체 모바일·PC E2E **210개 통과(11.5분)**. 신규 화면 연결 테스트는 두 환경 모두 통과했습니다.

브라우저 통합 테스트 작성 중 두 선택자(같은 제목의 두 필터 옵션, 혈통도 대표 카드와 작은 가족 카드의 클래스 구분)를 바로잡았습니다. 기존 공개 보인자 검증도 카드에서 상세정보로 이동한 표시 정책에 맞춰 유지했습니다. 기존 테스트를 삭제하거나 건너뛰지 않았습니다.
