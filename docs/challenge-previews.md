# 브리딩 도전 대표 외형

혈통도 상단의 기존 도전 패널 안에서 목표 설명·변경 잠금·보상을 왼쪽에, 대표 게코를 오른쪽에 표시한다. 상단 패널의 미선택 상태에는 임의의 게코를 표시하지 않는다. **전체 도전 목표 팝업에서도 5개 목표마다 설명 오른쪽에 같은 대표 외형을 표시**한다. 이미지 위 라벨 없이 기존 테라리움 배경과 `SpriteCanvas`를 사용하고, 전체 목표 보기 버튼과 각 목표 선택 버튼은 유지한다.

## 외형 설정과 실제 개체의 관계

`src/game/hardcore/challenge-previews.ts`의 `CHALLENGE_PREVIEW_RECIPES`에서 목표별 가상 대립유전자, Lilly/Axanthic 발현 및 고정 외형 시드를 관리한다. 기존 60개 다유전자 좌위의 합법 대립유전자 0~4와 기존 멘델 좌위만 사용한다. 중립값 2에 목표별 값을 적용하고 일반 개체와 같은 `specimen` 어댑터 → `patternTraits` → 96×96 8레이어 렌더러를 사용한다. 직접 RGB나 픽셀을 덮어쓰지 않는다.

| 도전 | 현재 엔진의 대표 외형 |
| --- | --- |
| 칠흑의 완성 | 명도·적색·오렌지 및 패턴 발현을 낮춘 다크 베이스 |
| 타오르는 태양 | 오렌지 발현이 강하고 밝은 패턴과 반점이 적은 개체 |
| 별이 내린 밤 | 대비되는 밝은 베이스에 고밀도 반점, 머리·몸통·꼬리에 분산 |
| 순백의 계승자 | Lilly White 이형접합과 높은 크림·측면 피복 |
| 흑백의 걸작 | 같은 고피복 Lilly와 발현 Axanthic 동형접합의 회색·백색 조합 |

단위 테스트는 각 대표 외형이 기존 목표 판정을 만족하고, 실제 상속 함수에서도 같은 외형 조합을 생성할 수 있음을 확인한다. **런타임 미리보기는 성공 판정 함수를 호출하지 않는다.** 이 모습과 똑같은 픽셀이나 시드로 부화해야 성공하는 것이 아니며 실제 성공 판정은 기존 `challenge-evaluator.ts`와 부화 이벤트를 그대로 사용한다. 특정 세이브의 부모 집단에 모든 목표 대립유전자가 존재한다는 보장은 아니다.

현재 엔진의 짙은 갈색 기반 다크 팔레트·공통 명암·크레스트/눈 구조·옆모습 표현을 그대로 사용한다. 팬텀 유전자, 완전 검정 피부, 사진 수준 전신 품질을 새롭게 구현한 것이 아니다. 색/패턴 차이는 현 게임에서 실제로 표현 가능한 범위다.

## 상태·성능·레이아웃

- 대표 입력은 목표별로 처음 필요할 때 한 번 생성하고 최대 5개만 캐시한다. 게임 RNG와 시계, 저장·경제·개체·알·유전 기록을 읽거나 쓰지 않는다. 어댑터 입력은 저장되지 않는 일시적인 렌더링용 개체다.
- `memo`로 분리한 미리보기와 안정적인 specimen 객체를 사용한다. 공통 Canvas의 기존 `useMemo`/effect가 같은 목표의 픽셀을 재사용한다. 목표 목록 열기/닫기나 잠금 턴 감소 때 **상단 패널의 Canvas**를 다시 그리지 않는다. 팝업의 5개 Canvas나 탭이 다시 마운트될 때는 기존 Canvas 방식대로 다시 그린다.
- 기존 패널 높이를 크게 늘리지 않도록 본문만 `minmax(0,1fr)` + 96~112px 두 열로 배치한다. 이름·설명·보상은 줄바꿈하고, 정사각형 캔버스 전체를 비율 유지해 프레임 안에 맞춘다. 성장 크기 배율을 추가 적용하지 않는다.
- 새 저장 필드나 이미지 파일은 없다. 구세이브는 기존 미선택 상태로 열리며, 선택된 목표는 기존 저장 값으로 즉시 복원한다.
- 향후 유전 엔진 변경 시 이 파일의 합법 유전체/레시피 변환만 교체한다. 대표 외형과 실제 목표 판정 기준은 독립적으로 검토해야 한다.

## 검증

- `npm test -- tests/challenge-previews.test.ts tests/breeding-challenges.test.ts`: **17개 통과**. 5개 대표 외형의 합법 유전체·기존 어댑터 일치·실제 상속 가능성·기존 목표 기준 충족, 픽셀 재현성과 캐시, 기존 잠금·부화·보상·저장 검사를 포함한다.
- 관련 모바일/PC 브라우저 **28개 시나리오 통과**: 도전 10개, 기존 혈통 14개, 공통 UI 4개. 최초 검사에서 430px 패널 높이(223px)가 설정한 220px 한도를 넘어 미리보기 최대 폭을 조정했고, 최종 도전 10개를 다시 통과했다. 기존 혈통·공통 UI 18개는 앞선 실행에서 통과했다. 무관한 전체 테스트는 반복하지 않았다.
- 실제 Canvas의 3배 확대 픽셀을 96×96 논리 픽셀로 읽어 공통 렌더러 출력과 완전 일치를 확인했다. 미선택 시 이미지 없음, 실제 목표 변경 즉시 갱신, 새로고침 시 외형/저장 일치, 미리보기를 보거나 목표 목록만 열었을 때 저장 데이터 불변을 검증했다.
- Canvas `drawImage`를 계측해 목표 목록 열기/닫기와 실제 1턴 진행 이후 추가 그리기 **0회**를 확인했다. 실제 부화 성공·최초 보상 1회·10턴 잠금·자동 칭호 승급·수동 수령 흐름도 기존 테스트로 유지했다.
- TypeScript 검사·프로덕션 빌드·아트 PNG/런타임 해시 검사 통과. 유전·부화·보상·저장·공통 렌더러 코드는 변경하지 않았다.
- Chromium 터치 에뮬레이션 **360×640, 390×844, 430×932**에서 모든 목표의 정사각형 이미지 전체 표시, 설명과 이미지 분리, 텍스트/페이지 가로 넘침 없음 확인. 패널 높이 각각 **201 / 209.69 / 218px**. [15개 측정값](challenge-previews/layout.json). 실물 기기 및 Safari 검사는 수행하지 않았다.

## 전체 목표 선택 팝업 확장

각 목표의 설명과 힌트 옆에 기존 `ChallengePreview` 컴포넌트를 그대로 재사용한다. 위 패널과 동일한 레시피/고정 시드/캐시를 사용해 같은 목표가 같은 모습으로 보인다. 완료한 목표의 실제 최초 달성 개체 기록은 별도로 보존하며, 목표를 고르거나 이미지를 보는 동작으로 해칭 판정·보상을 실행하지 않는다. 팝업 목록은 기존처럼 세로 스크롤한다.

모바일에서는 목표 카드 안의 본문만 두 열로 배치하고 이미지는 88~120px 정사각형으로 표시한다. 제목·완료 상태·보상·선택 버튼은 기존 위치에 유지한다. 텍스트는 자연스럽게 줄바꿈하며, 잠금 중이나 완료한 목표의 참고 외형도 볼 수 있다.

추가 검증: 대표 외형 단위 **6개**, 모바일/PC 도전 E2E **12개**, 타입 검사와 프로덕션 빌드 통과. 5개 목표 이미지의 실제 픽셀 일치, 360/390/430px의 이미지 전체 표시와 텍스트 분리/가로 넘침 없음, 44px 선택 버튼, 목록 조회 시 저장 불변성, 선택 후 10턴 잠금과 상단 동일 외형 갱신을 확인했다. 기존 성공 보상·새끼 수령과 상단 Canvas 재사용 검사도 통과했다.
