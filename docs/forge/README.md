# B-ORIGIN-01 본게임 이식

정식 `/` 게임의 컬렉션·상점·부모·교배·부화·혈통·도전 초상화가 승인된 `b-origin-01-companion-lineage-1`을 사용한다. 기존 `/lab`, `/lab/patterns`, `/lab/breeding`의 과거 엔진과 아트는 비교·회귀용으로 남는다. 게임 화면에서 엔진을 선택하는 기능은 추가하지 않았다.

360px 실제 게임과 8계열·16개 시드의 Canvas 캡처를 로컬에서 검토했다. 동일한 이전 개체 6마리도 기준 커밋을 별도 체크아웃해 같은 390px 화면에서 직접 실행하고, 유전 기록을 보존한 새 화면과 비교했다. 캡처는 로컬 검토 산출물이며 이 공개 저장소에는 포함하지 않는다. 아래의 `forge-integration` 검사는 로컬 `docs/forge/game-360.png`·`native-gallery.png`를 생성한다.

## 연결 지점

| 경로 | 역할 |
| --- | --- |
| `src/forge/engine`, `src/forge/mask-editor` | 실험실의 수정하지 않은 순수 소스 62개. B-ORIGIN-01·7영역·보호·3단계 명암 포함 |
| `src/forge/index.ts` | 가져온 유전·발현 API |
| `game/hardcore/forge-genetics.ts` | 새 창시자 확장 사본, 부모별 사본 상속·검증 |
| `game/hardcore/forge-appearance.ts` | 같은 실제 렌더 결과에서 이름·점유율·연결·반점·분양가 입력을 계산 |
| `game/hardcore/adapter.ts`, `forge/surface.ts` | 모든 게임 Canvas 연결. 배경만 투명 처리하며 신체 RGBA는 승인 결과 그대로 유지 |
| `game/hardcore/migrate-forge.ts`, `storage/hardcore.ts` | 기존 기록 이전·동일 트랜잭션의 원본 아카이브 |
| `game/hardcore/forge-challenges.ts` | 새 도트의 실제 발현에 맞는 목표 판정 |

원본 모듈별 SHA-256은 [source-manifest.json](source-manifest.json)에 있다. 가져오기 전 원본의 25개 공통 코어 파일은 본게임 기준 커밋 `c934363f854b47c154d8d8127d6d23abbe692e9e`와 바이트 단위로 일치했다. 공통 코어는 중복 복사하지 않고 원래 경로를 사용한다. `GeneticsRecord`에는 선택적인 확장 기록 타입만 추가했다.

소스의 고정 30개 샘플 매개변수·관찰값·RGBA 해시는 `tests/fixtures/forge/lineage-v1.json`에 그대로 보관했다. 테스트는 본게임 안에서 재렌더해 원본과 비교한다. 원화 준비·컴파일 스크립트로 아티스트 PNG를 덮어쓰지 않는다.

## 데이터와 상속

저장 외피는 v10, 게임 규칙은 4를 유지한다. 현재 엔진의 사용 여부는 게임의 `forge: {version: 1}`로 구분한다. 각 유전 기록은 다음 확장을 가진다.

```ts
genetics.forge = {
  version: 1,
  extensions: {                    // 기존 미기록 개체에서는 생략
    version: 5,
    phantom: ['N', 'ph'],           // N / ph / null 두 사본
    emptyBack: ['N', 'Eb'],         // N / Eb / null 두 사본
    whiteout: ['N', 'Wo'],          // N / Wo / null 두 사본
    lateral: {
      version: 1,
      shape: /* 0~4 또는 null 대립유전자 4쌍 */ [],
      continuity: /* 같은 형식 4쌍 */ [],
    },
    veil: {
      version: 1,
      density: /* 0~4 또는 null 대립유전자 6쌍 */ [],
    },
  },
};
```

위 배열은 형식 설명이며 실제 저장에는 지정된 수의 사본이 필요하다. 자손은 각 좌위에서 아비 사본 하나·어미 사본 하나를 받는다. 미기록 부모에서 온 사본은 `null`이다. 옆무늬와 흰 베일은 게임용 다유전자 근사이며 모프명 자체는 상속하지 않는다. 릴리의 흰 베일은 비릴리에서도 전달되지만 릴리에서만 가시적으로 작용한다. 세이블·하이웨이는 기존 잠정 C/S/H 좌위를 그대로 사용한다.

기존 3개 멘델 좌위와 60개 다유전자 좌위, 게임 전용 건강 좌위의 알고리즘·RNG 도메인은 보존했다. 새 확장만 별도 RNG 도메인으로 상속한다. 게임의 수정 시드는 128자를 넘을 수 있고 성별 RNG는 기존 `sex` 도메인을 사용하므로, 실험 도구의 짧은 입력용 `createOffspring` 래퍼를 게임에 그대로 호출하지 않는다. 일치하는 공통 코어의 `inherit`·`inheritPoly`와 확장 상속을 기존 배아 팩토리에 연결했다. 모든 사본·성별·외형 시드는 수정 시 확정되며 부화 시 재추첨하지 않는다.

## 이전과 복구

현재 신규 생성은 `newForgeGame`, 로드·JSON 복원은 `readForgeSave`·`parseForgeBackup`을 사용한다. 기존 `newGame`·`readSave`·`parseBackup`은 과거 순수 회귀 검사와 저장 재현용으로 유지하므로 새 제품 진입점에서 호출하지 않는다.

기존 `active`는 검증 후 개체·알·매물 부모·교배 당시 스냅샷·확정 배아·완료 도전 초상화에 엔진 표식만 추가한다. 실제 확장 사본은 추정하지 않는다. DNA가 없는 이전 개체는 원래 공개된 외형 수치의 렌더 전용 투영을 사용하며 `genome: null`을 유지한다. 실제 DNA가 있는 개체의 63개 좌위는 그대로 새 재질·무늬 엔진에 입력한다.

v10의 첫 이전은 `archive-v10-<다음 저장 리비전>`에 원본을 보관하고 같은 IndexedDB 트랜잭션에서 `active`를 교체한다. 반복 로드로 다시 이전하지 않는다. 기존 이전 버전의 아카이브도 보존한다. 턴·이름·가격 기록·혈통·성별·씨앗·수거/수령 상태·확정 부화 결과·완료 보상·카페 러시 수령 상한은 변경하지 않는다. 이후 새로 갱신되는 매물과 새 거래 견적은 새 엔진을 사용한다.

## 관찰과 목표

패턴은 기존 단색·명암에 재질로 적용한다. 측면 상하 사이에 새 구조선을 만들지 않으며 기존 보호 픽셀은 유지한다. 신체는 원본 결과와 바이트 단위로 같고 검은 도구 배경만 표시 단계에서 비운다. 성장 크기 50%·75%·100%는 기존 CSS 표시를 한 번 적용한다.

원본 이름에 누락된 엠티백·화이트아웃·화이트월·포트홀·리버스 핀은 실제 가시적 관찰값이 있을 때만 부가 명칭에 넣는다. 숨은 팬텀 보인자·아잔틱 보인자·비릴리의 베일 사본은 이름·분양가·필터로 공개하지 않는다. 확장 형질을 위한 공개 지식 추론과 확률 UI는 이번 이식에 새로 추가하지 않았으며, 기존 3개 좌위의 공개 정보 예측을 유지한다.

새 목표는 `evaluatorVersion: 2`를 기록한다. 기존 완료 기록은 버전 1 그대로 유지하고 과거 기준으로도 재판정하지 않는다.

| 새 목표 | 초기 게임 기준 |
| --- | --- |
| 칠흑 | 실제 기저색 휘도 ≤58, 측면 기저색 ≥72%, 비릴리·비아잔틱 |
| 솔리드 오렌지 | 실제 오렌지 발현, orange 점수 ≥0.75, 측면 기저색 ≥70%, 반점 ≤5 |
| 슈퍼달마시안 | 작은 실제 반점 ≥32개, 머리·몸통·꼬리 각 ≥3개 |
| 고피복 릴리 | 실제 베일 ≥0.85, 신체의 밝은 면적 ≥60% |
| 릴잔틱 | 위 릴리 조건 + 아잔틱 발현 |

새 native 반점 모델의 상한은 48개이므로 과거 65개 기준을 현재 목표에 적용하면 달성할 수 없다. 위 수치는 브리더 기준이 아닌 조정 가능한 게임 기준이다. 다섯 목표 모두 편집하지 않은 실제 상속·부화 결과로 달성 가능함을 검사한다. 좌우 연결 수치는 단일 옆모습의 투영이며 반대편 관찰을 주장하지 않는다.

## 재현과 검증

```bash
npm ci
npm run typecheck
npm test -- --maxWorkers=1
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

`forge-source`는 승인 소스 62개와 샘플 30개를 검사한다. `forge-migration`은 새 매물·기존 기록·대기 중 교배/알·역사적 도전·긴 수정 시드·성장 후 픽셀·공개 정보·손상 거부·캐시를 검사한다. `forge-challenges`는 다섯 목표의 실제 상속을 검사한다. `forge-integration`은 모바일/PC 실제 Canvas의 16개 시드·8계열 픽셀과 IndexedDB 원자적 이전을 확인한다. 기존 브라우저 시나리오의 원본 fixture는 보존하고 현재 화면의 기대값에만 동일한 엔진 이전을 적용한다.

현재 게임 캐시는 불변 개체 객체와 최근 64개 시각 입력을 사용한다. 게임 캐시에서는 디버그 레이어를 보관하지 않고 최종 픽셀을 사용한다. 순수 렌더 API의 디버그 레이어는 유지한다.

CI는 기능 검사를 2개 워커에서, 실제 시각·프레임·탭 시점을 측정하는 크레 러시 검사를 1개 워커에서 실행한다. 두 명령의 합이 전체 검사이며, 각각의 출력·실패 추적은 다른 하위 폴더에 보관한다. 무거운 렌더링 중에도 발품팔기를 중복 결제하지 않도록 저장 완료 뒤부터 기존 400ms 연속 클릭 제한을 적용한다.

이식은 성체 포즈의 재질·무늬를 다룬다. 입체 비늘, 별도 성장 원화, 새로운 질병·생존 확률은 추가하지 않는다. 세이블/하이웨이 슈퍼·복합 조합은 원래 잠정 모델이며, 새 목표나 근거 없는 치사율을 부여하지 않는다. 기존 아잔틱은 한 호환 라인 모델이다.
