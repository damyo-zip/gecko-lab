# 교배 제한 해제·유전적 위험·교배 팝업

정식 `/` 게임(저장 v9 / 턴 규칙 4)은 근친, Lilly × Lilly 및 잠정 복합 좌위 조합을 **경고 확인 후 허용**합니다. 성별·보유 생존 상태·12턴 성체·60턴 은퇴·회복·진행 중 산란·2칸 예약 조건은 그대로입니다. 별도 `/lab/breeding`와 v5/v6 단위 fixture는 당시 규칙을 검증하는 회귀 시뮬레이터로 보존합니다.

## 실제 플레이

성체 상세의 **부모로 선택**, 인큐베이터 빈 슬롯 또는 교배 도구에서 팝업을 엽니다. 부모 선택 → 혈통 비교/공개 유전 정보 → 교배하기 순서입니다. 위험이 겹치면 한 확인창에 모아서 표시하며, 취소는 게임 상태를 쓰지 않습니다. 일반 교배는 추가 확인 없이 시작합니다. 확인은 현재 리비전·두 부모·공개 경고 내용에 묶여 있어 부모/진행 상황이 바뀐 뒤 오래된 확인을 재사용하지 않습니다. 기존 저장 잠금과 원자적 쓰기로 연속 클릭도 한 번만 처리합니다.

새 재고에는 기존 잠정 좌위의 C/S/H도 실제 부모에서 상속된 매물로 등장합니다. 처음의 저렴한 노멀 성체 한 쌍·4마리 매물·기존 가격 공식은 유지하며, 저장된 이전 매물은 재생성하지 않습니다.

게임 헤더·탭을 별도로 복제하지 않은 모달입니다. 기존 테라리움/배너 **부분 에셋**과 실제 두 개체의 Canvas를 조합하며, 화면 전체를 이미지로 붙이지 않습니다. 실제 나이는 턴과 게임 일수로 표시합니다. 정보·혈통·상세·위험 확인은 독립적으로 열고 닫힙니다. 부모 선택은 모바일 기본 선택창을 사용합니다. 교배 버튼 아래에 상시 정보 패널은 없습니다. PWA 캐시 14에 팝업 배경 에셋도 포함합니다.

## 근교계수 F

`src/game/pedigree-risk.ts`는 기록된 **전체 조상**을 사용합니다. 두 부모의 kinship `φ(f,m)`이 자손의 F입니다.

- `φ(i,i) = (1 + F_i) / 2`
- 다른 개체 간 `φ(i,j) = (φ(아버지_i,j) + φ(어머니_i,j)) / 2`
- 조상이 먼저 오도록 순서를 만들고, 필요한 쌍만 메모합니다. 반복 조상 및 이미 근친교배된 조상도 포함하며 단순 공통 조상 수/세대 수를 쓰지 않습니다.
- 재귀 호출 대신 명시적 스택을 사용하고 순환 혈통은 오류로 처리합니다. 부모·자식, 친형제, 이복형제, 사촌, 직계 후손, 먼 공통 조상을 구분합니다.

비근친·비혈연 창시 개체 가정에서 부모·자식/친형제 자손 F=25%, 이복형제=12.5%, 사촌=6.25%입니다. 반복 친형제 교배는 25% → 37.5% → 50% → 59.375%처럼 계산됩니다. **F는 질병 확률이 아닙니다.** 기록 없는 시조·부모는 상호 비혈연/비근친으로 가정합니다. 완전한 비혈연이 확인되었다는 뜻은 아니며 혈통 비교/경고에 이 한계를 표시합니다. 판매·사망·외부 부모도 같은 기존 개체 기록을 사용합니다.

## 실제 대립유전자 상속과 가상 열성 건강 모델

기존 60개 가상 외형 좌위·멘델 유전·보인자 추론·유전자 기반 무늬/명칭·시장 가격을 재사용합니다. 친족이라는 이유로 외형 점수/하트/생존율을 차감하지 않습니다. 형질 고정과 해로운 변이의 동형접합은 부모의 실제 대립유전자 전달 결과입니다. 보인자는 정상일 수 있고, 비혈연 부모에서도 같은 변이가 만나면 영향이 발생할 수 있습니다.

`src/genetics/health.ts`에 **현실에서 확인된 게코 질병 유전자와 관계없는 게임 전용** 독립 열성 좌위 두 개를 추가합니다. 모델 버전 1의 고정 밸런스 값입니다.

| 가상 좌위 | 보인자 | 변이 동형접합의 영향 |
| --- | --- | --- |
| `embryonic-vigor` / v | N/v는 영향 없음 | 생존 가능한 수정란이 기본 부화 판정을 통과한 경우, 추가 발달 성공 계수 0.75 |
| `fertility` / f | N/f는 영향 없음 | 해당 부모의 번식 계수 0.8. 부모별 계수를 곱해 기본 수정 확률 0.95에 적용 |

창시 개체의 사본별 변이 초기 빈도 0.08은 게임 설정이며 실제 집단 빈도가 아닙니다. 개체별 고정 시드로 서로 다른 유전형을 생성합니다. 자손은 좌위마다 부모에게서 한 사본씩 상속합니다. F·세대·교배 횟수를 확률에 곱하지 않습니다. 무작위 질병, 기형 이벤트, 성체 하트 벌점, 추가 수명 페널티를 도입하지 않습니다. 일반 야생형/보인자의 기존 5% 무정란·95% 기본 부화 확률은 유지됩니다. 가상 변이의 동형접합인 경우에는 해당 유전적 효과가 추가로 적용됩니다.

건강 유전형은 UI/경고/가격에 직접 노출하지 않습니다. 경고와 예측은 **공개 지식 및 기록된 혈통**을 사용하고, 미확인 열성 보인자나 알의 미공개 결과를 조회하지 않습니다.

## Lilly 및 복합 좌위

Lilly 이형접합 두 부모의 모델상 수정 시점 분포는 Normal 25% / Lilly 50% / Lw/Lw 비생존 25%입니다. 해당 좌위의 비생존만 제외한 조건부 비율은 1/3 : 2/3이며 전체 부화율과 구분합니다. 알마다 독립적으로 결정하고, 두 부모가 Lilly라는 이유로 알 전체를 실패시키지 않습니다.

완전한 고급 유전체가 있는 두 부모는 **고급 상속 경로 한 번**으로 유전 결과를 생성하고 기본 캐시 유전형을 거기서 도출합니다. 이전 수치 모델 부모가 있으면 기존 기본 멘델/평균·변이 경로를 보존합니다. 혼합 이전 교배의 복합 좌위는 `unresolvedComplex`에 실제 전달된 알려진 사본과 `null`(진짜 미확인 사본)을 보존하며, 모르는 사본을 정상 n으로 꾸며내거나 정확한 확률을 부여하지 않습니다. 미확인 외형 좌위를 복원하지 않고 기존 외형 버전을 유지합니다.

Cappuccino / Sable / Highway의 같은 좌위 모델·C/C, C/S, C/H, S/S, S/H, H/H 분류는 기존 잠정 모델입니다. 이들 조합과 정보가 불완전한 복합 교배도 실행 가능합니다. **건강 위험 보고가 수정 시점 100% 비생존을 증명하는 것은 아니므로**, 이 계열을 임의의 치사 확률/전부 실패로 바꾸지 않습니다. 복합 좌위 표는 대립유전자 분포만 표시하고 과학적으로 확인되지 않은 생존 조건부 비율을 표시하지 않습니다. 가상 건강 모델을 특정 실제 모프의 검증된 위험인 것처럼 연결하지 않습니다.

근거 구분:

- 기존 [Lilly 모델 근거](https://www.corchgeckos.com/lillywhite.html): 브리더 관찰 기반 불완전 우성/동형접합 비생존 작업 모델. 분자 검사·개별 폐사 시점 모델이 아닙니다.
- [Foundation Genetics PSA](https://lmreptiles.com/fg-scapppsa/) (접근 확인 2026-10-14, 페이지 v1.2 / 2026-09-08): 같은 좌위·Super Cappuccino/Sorak/Luwak 등 건강 위험 관찰과 강한 경고가 있습니다. 이를 모든 복합 수정란의 확정 치사율로 확장하지 않습니다. 잠정/논쟁/미검증 구분은 기존 `loci.ts`와 자료 링크를 유지합니다.
- 단일 호환 라인 Axanthic의 열성 모델, 브리더 관찰과 독립 좌위 가정은 기존과 같습니다. 서로 다른 실제 아잔틱 라인의 호환성·연관 유전·확정된 질병 확률을 주장하지 않습니다.

## 배아·산란·부화 기록

`Embryo`는 부화 전 후보이며, `development`의 생존 가능 여부·원인과 실제 유전형을 저장합니다. 비생존 후보는 정상 `individuals`에 들어갈 수 없고, 저장 검증도 이를 거부합니다. 비생존 결과가 나와도 교배/저장이 예외로 중단되지 않습니다. 살아 태어나는 개체는 배아의 고정 유전형·고유 시드·부모·세대를 유지하고 배아 전용 `development` 필드를 제거합니다.

- 교배 시 두 알 결과/수정 여부 확정 → 2칸 예약 → +2턴 산란/자동 배치 → +4턴 판정 → 4턴 휴식 유지.
- 실패 원인의 순서는 **무정란 → 유전적 비생존 → 기본 부화 실패 → 가상 배아 발달 실패**입니다. 하나의 결과에 둘 이상의 실패를 겹쳐 추첨하지 않습니다. 비생존 수정란에는 일반 부화 판정을 다시 하지 않습니다.
- 내부 `failure`: `infertile`, `genetic`, `hatch`, `health`. 유전적 비생존 원인은 배아의 `development.causes`에 별도로 보존합니다. 해로운 가상 대립유전자 자체는 공개하지 않습니다.
- 실패한 알은 기록으로 남고 예약 공간은 반환합니다. 보상·희귀 컬렉션·정상 개체로 생성하지 않습니다. 성공 부화만 기존 부모 지식의 관찰 증거가 됩니다.
- 저장된 수정 결과·배아·완료 상태·처리 턴으로 재접속/같은 턴 이벤트 재실행 시 산란·부화·개체 생성이 중복되지 않습니다.

## 저장 v9와 이전 세이브

v2–v8의 원본을 먼저 해당 버전 검증/체크섬으로 검사하고 기존 마이그레이션을 거쳐 v9로 이전합니다. IndexedDB의 같은 쓰기 트랜잭션에서 원본 아카이브와 새 슬롯을 기록합니다.

v8→v9는 기존 개체·혈통·외형·유전형·가격·알·교배 이력을 변경하지 않고 가상 `healthGenome`만 추가합니다. 부모가 먼저 오는 순서로 게임 시드+불변 ID를 사용해 창시 변이를 결정하고 자손은 실제 부모에게서 상속해 초기화합니다. 동일 ID의 개체·알 배아·교배 스냅샷·상점 영수증은 동일한 건강 유전형을 가집니다. 이전 개체의 기존 외형/단일 유전자 정보를 가상 변이로 재해석하지 않습니다.

이미 진행 중/완료된 교배는 `riskModel: null`로 두어 **이미 확정된 수정·유전·기존 실패·부화 결과를 바꾸지 않습니다**. 새 교배만 모델 1의 부모 건강 스냅샷과 배아 발달 기록을 만듭니다. JSON 백업·복원, 원본 아카이브, 다른 탭의 충돌 차단은 기존 구조입니다.
