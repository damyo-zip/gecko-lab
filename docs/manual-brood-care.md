# 산란·부화 수동 관리

## 플레이

- 교배 시 기존 두 칸 예약을 유지합니다. +2턴에 한 번만 2알을 산란하며, 예약은 수거 대기 알로 이전됩니다. 암컷은 산란부터 기존 4턴 휴식을 갖습니다.
- 컬렉션의 암컷 대표 이미지와 카드에 두 알이 하나의 버튼으로 표시됩니다. 한 번 누르면 해당 교배의 두 알을 함께 수거합니다. 여러 클러치를 미수거한 경우 한 쌍씩 수거합니다.
- **수거 턴 +4턴**에 기존 확정 유전형과 기존 무정란·부화·건강 판정으로 결과를 공개합니다. 미수거 알은 부화 카운터가 진행되지 않습니다.
- 부화한 새끼는 깨진 껍데기 앞에 표시됩니다. 공통 `Sprite`의 기존 해칭 50% 표시만 사용하며 추가 축소는 없습니다. 터치해야 컬렉션에 등록됩니다.
- 무정란·기타 부화 실패 알은 변색된 모습으로 슬롯에 남습니다. 한 번 누르면 슬롯을 반환하고 실패 기록은 보존합니다.
- 수거 전 알, 수령 전 새끼, 제거 전 실패 알은 턴이 지나도 슬롯 예약을 유지합니다. 수령은 예약 한 칸을 보유 한 칸으로 전환하므로 추가 공간을 중복 청구하지 않습니다.
- 산란·부화·실패를 위한 새 알림이나 애니메이션은 없습니다. 어미가 분양되거나 사망한 뒤에도 인큐베이터의 ‘알 수거 대기’에서 같은 클러치를 수거할 수 있습니다.

## 데이터와 호환성

저장 v10, 기존 규칙 버전 4를 사용합니다. 알의 `care` 버전 1에 `collectedTurn`과 `settledTurn`을 기록합니다. 기존 `status`는 판정 결과를, `care`는 플레이어 처리 여부를 나타냅니다. 완료된 알을 삭제하지 않으므로 원래 배아·유전형·부모·실패 원인·번식 이력이 남습니다.

수정 시 저장한 배아와 산란 일정은 재추첨하지 않습니다. 수거가 늦어지면 알의 출생 예정 턴·날짜와 성체 예정 날짜만 실제 부화 예정일로 이동합니다. 수정 시의 원본 자손 스냅샷은 별도로 보존하고 검증합니다.

사용자 확인에 따라 **실제 나이는 부화 턴부터** 계산합니다. 인큐베이터는 저장된 부화 당시 모습(해칭, 50%)을 표시하고, 수령 시 기존 6/12턴 규칙으로 현재 성장 단계를 계산합니다. 미수령 새끼는 보유 개체가 아니므로 컬렉션의 자동 급여·교배 대상에 포함하지 않습니다.

이전 저장은 검증 후 v10으로 이전하며 실제 IndexedDB 이전 시 원본을 같은 트랜잭션으로 아카이브합니다. 이전 부화 중 알은 기존 시작일·남은 시간·유전 결과를 유지하고, 결과가 나면 수동 수령/제거를 기다립니다. 이미 부화·등록되거나 실패 처리된 과거 기록은 다시 수령·제거 대상으로 돌리지 않습니다. 크레 러시 기록·미수령 급여·수령 상한과 Worker 최적화도 그대로 유지합니다.

## 주요 파일

- `src/game/hardcore/brood-care.ts`: 수거·수령·제거, 출생 메타데이터, 이전.
- `brood-care-validation.ts`, `lifecycle-validation.ts`, `validation.ts`: 대기 상태·쌍 수거·공간·원본 상속 기록 검증.
- `season.ts`, `survival.ts`, `play.ts`: 기존 턴 처리와 예약에 수동 단계를 연결.
- `src/components/hardcore/collection.tsx`, `incubator.tsx`, `incubator-state.ts`, `incubator-egg.tsx`: 실제 상태에 연결한 알·새끼 터치 UI.
- `src/game/hardcore/save.ts`, `src/storage/hardcore.ts`: v10 저장과 원본 아카이브.

## 검증

새 단위 테스트는 미수거 7턴 대기, 수거 후 정확히 4턴, 반복 입력, 수령 전 12턴 대기와 실제 나이, 실패 알 제거, 두 어미의 동시 예약, 한 어미의 복수 미수거 클러치, 어미 분양 후 수거, 상태 손상 거부 및 JSON 복원을 검증합니다.

모바일/PC 브라우저에서 실제 터치/마우스로 수거→부화→새끼 수령·무정란 제거→새로고침을 실행했습니다. 360·390·430px 가로 넘침, 깨진 알/새끼의 레이어, Canvas 실측 50%·중앙 정렬·정사각 비율·스무딩 비활성화, 기존 성장 표시 회귀를 확인했습니다. 기존 게임 시나리오는 자동 등록을 가정하던 부분에 명시적인 테스트용 플레이어 수거·수령 행동을 추가했으며 테스트를 삭제하거나 건너뛰지 않았습니다.

최종 검증(2026-10-15):

- `npm run typecheck`, `npm run build`: 통과.
- `node scripts/compile-gecko-art.mjs --check`: 기존 PNG/런타임 해시 일치.
- `npm test`: 26개 파일, **304개 통과**(67초). 신규 상태 전환 테스트 8개 포함.
- `PLAYWRIGHT_BROWSERS_PATH=/tmp/gecko-ci-browsers npm run test:e2e -- --workers=2`: **204개 통과**(11.4분), 모바일/PC 각 102개. 기존 테스트를 삭제하거나 건너뛰지 않았습니다.
- v9 실제 IndexedDB 원본 아카이브와 연속 두 번 클릭, 기존 성장 50/75/100%, 크레 러시 300개체/20마리 근무와 중복 급여 방지도 포함합니다.
