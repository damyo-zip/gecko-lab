# 상점 한 화면 배치와 즉시 행동

2026-10-16 KST. 상점의 시각 스타일과 기존 게임 규칙을 유지하면서 공간과 클릭 단계를 정리했습니다.

## 변경 내용

- 상점의 턴 결과 안내 상자와 가격표/매물 갱신 안내 문단을 JSX에서 제거했습니다. CSS로 숨기지 않으며 이 영역의 패딩·마진·간격도 남기지 않습니다. `game.notices` 기록, 자동 급여, 사료 차감, 턴 진행과 재고 갱신은 기존 엔진 그대로입니다.
- 발품팔기를 누르면 확인 팝업 없이 기존 `refreshShop`을 호출합니다. ₩2,000 차감과 4개 매물 생성은 기존 행동·IndexedDB 저장을 사용합니다. 기존 동시 행동 잠금에 400ms UI 입력 보호를 더해 빠른 저장 후 발생하는 이중 탭도 한 번으로 처리합니다. 이후 의도적으로 다시 누르면 새 매물을 정상 갱신합니다.
- 공간 부족 버튼은 실제 `disabled` 대신 별도 상태 클래스를 사용해 원래의 **opacity 0.6, 배경, 색상, 테두리, 그림자 없음, 글자와 크기**를 유지합니다. 터치하면 허브의 기존 **사료 및 사육장 관리** 팝업이 열립니다. 닫으면 상점을 유지하며, 사육장 구매 후 버튼이 즉시 구매하기로 바뀝니다. 게코가 자동 구매되지는 않습니다.
- 자금 부족·구매 완료·저장 중 상태의 실제 비활성화는 유지합니다. 공간 부족을 우회해 구매하지 않으며 사육장 가격과 용량·예약 슬롯 계산도 바꾸지 않습니다.

## 높이 배치

기존 공통 헤더와 턴 버튼·하단 내비게이션의 위치·크기·스타일은 유지합니다. `100dvh` 공통 레이아웃이 확보한 **중앙 행의 실제 높이**를 사용하고, 상점 영역에만 Flex/Grid와 이름이 있는 크기 컨테이너를 적용합니다.

일반 화면에서는 기존 이미지의 너비/비율 및 높이 상한을 유지합니다. 압축 규칙은 599px 이하의 상점 중앙 영역에만 적용하므로 데스크톱의 큰 이미지에는 적용되지 않습니다. 짧은 중앙 영역에서는 카드 사이 간격과 내부 상하 패딩, 텍스트 여백을 먼저 줄입니다. 그래도 필요한 경우 이미지 **프레임**만 남은 높이 안에서 축소하며, 기존 정사각 캔버스와 성장 단계의 50/75/100% 배율은 그대로입니다. 이름·모프·나이·가격·버튼 글자 크기와 44px 구매/부모 터치 영역을 줄이지 않습니다.

기존 `.reference-content`의 `overflow:auto`를 유지합니다. 페이지나 카드를 숨겨 한 화면처럼 보이게 하지 않습니다. 360×640에 별도 44px 상단/34px 하단 안전 여백까지 강제하는 경우, 또는 가로 화면처럼 물리적으로 최소 콘텐츠보다 낮은 경우에는 중앙 내부 스크롤로 모든 매물에 접근합니다. 일반적인 노트10+ 크기의 세로 브라우저에서는 안전 여백을 적용해도 한 화면에 표시되도록 검증합니다.

## 검증 범위

- 360·390·412·430·480px 너비와 640~932px 높이의 2열×2행, 모든 정보/버튼, 가로 넘침, 스크롤과 CTA/내비게이션 겹침을 확인합니다.
- 수정 전 측정한 글자 크기와 일반 화면 이미지 높이를 비교합니다. 기존 비활성 버튼과 현재 공간 부족 버튼의 실제 computed style도 동일한지 확인합니다.
- 44/34px 안전 여백이 실제 CSS 값으로 적용됐는지 검사한 뒤 배치를 측정합니다. 테스트용 단순 `.shop-shell` 규칙이 공통 기본값에 덮이는 문제를 찾아 선택자와 검사를 수정했습니다.
- 공간 부족 터치 시 게임 상태/매물/자금 불변, 닫기 시 상점 유지, 기존 사육장 확장의 정확한 비용/용량 증가, 이후 구매/중복 구매 차단·새로고침 복원을 확인합니다.
- 같은 프레임 연속 클릭과 120ms 뒤 두 번째 탭에서 한 번만 차감되는지, 입력 보호 이후 새 요청은 실행되는지, 저장/재접속 후 매물이 유지되는지 확인합니다.
- UI 행동의 결과를 기존 `actWithTime` 결과와 비교해 매물 유전체·가격·부모·시드와 턴 급여/갱신이 동일한지 확인합니다. Node/Chromium `Math.exp`의 한 ULP 차이는 기존 프로젝트 관례대로 **새 매물의 파생 외형 점수만** 소수 12자리에서 비교하고, 기존 기록·유전형·자금·가격·ID는 정확히 비교합니다. 실제 데이터를 반올림해 저장하지 않습니다.

### 실행 결과

- `npm run typecheck`: 통과.
- `npm test`: 28개 파일, **326개 통과**.
- `npm run build`: 통과.
- `node scripts/compile-gecko-art.mjs --check`: 기존 PNG/런타임 아트 해시 일치.
- `PLAYWRIGHT_BROWSERS_PATH=/tmp/gecko-ci-browsers npm run test:e2e -- --workers=2`: **216개 실행, 215개 통과, 1개 실패**. 상점 기존/신규와 공통 UI **16개는 모두 통과**했습니다.
- 실패한 기존 모바일 크레 러시 20마리 테스트만 `--project=mobile-chromium --grep '20 targets' --repeat-each=3 --workers=1`로 동일 코드에서 재실행: **3회 연속 통과**.

전체 실행의 실패는 20회 포획 중 13번째가 PERFECT 대신 GOOD이어서 예상 급여보다 500원 적었던 사례입니다. Trace에서 해당 타깃의 진행도 0.8017을 읽은 뒤 네이티브 탭 명령 시작까지 120.36ms가 걸렸고, 결과는 19 PERFECT/1 GOOD이었습니다. 자동화 입력 타이밍에 민감한 사례로 남기며 전체 검사가 한 번에 모두 통과했다고 표시하지 않습니다. 크레 러시 코드·판정·급여·해당 테스트는 수정하지 않았습니다. 같은 전체 실행의 데스크톱 사례와 이후 모바일 3회는 모두 통과했습니다.
