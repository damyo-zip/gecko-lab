# 카카오톡 완전 전체화면 게임 실행 실험

실험용 링크: https://gecko-lab.vercel.app/fullscreen-play

기존 `/start`의 설치 우선 흐름 및 `/`의 일반 게임 진입은 그대로 둡니다. 이번 페이지는 **설치 없이 카카오톡에서 게코랩을 플레이**할 때의 실제 느낌을 비교하는 독립 실험입니다.

## 동작

1. 카카오톡으로 `/fullscreen-play`을 연다.
2. `전체화면으로 게임 시작` 버튼을 누른다.
3. `document.documentElement.requestFullscreen()`을 사용자 터치 이벤트 안에서 바로 실행한다.
4. 성공과 `fullscreenElement`을 확인한 후 같은 React 문서 안에서 기존 `HardcoreHub`을 렌더링한다.
5. 페이지 이동이나 리다이렉트가 없으므로 전체화면 상태를 유지할 수 있다.
6. Android 상단 상태 바와 하단 시스템 탐색까지 숨겨질 수 있다. 아래로 스와이프하여 탐색을 복구하면 전체화면이 해제된다.
7. 전체화면이 해제되면 게임은 계속되며, 상단 작은 버튼으로 다시 전체화면을 켤 수 있다.
8. 전체화면이 미지원/차단되면 오류를 설명하고 같은 URL에서 일반 화면으로 플레이할 수 있다.

## 변경 범위

- 게임 허브, 유전·외형 엔진, 인큐베이터, 상점, 저장 스키마, 기존 홈 라우트는 변경하지 않았습니다.
- 같은 도메인과 브라우저 저장소를 사용하므로 기존 게임 저장을 동일하게 불러옵니다. **카카오톡과 Chrome의 저장소는 공유된다는 보장이 없습니다.**
- 완전 전체화면에서는 시스템 상태 바·내비게이션도 사라지는 것이 현재 Galaxy/KakaoTalk 실기기 실험에서 관찰된 동작입니다.
- 앱 내 링크로 다른 경로로 이동하거나 새로고침하면 전체화면이 해제될 수 있습니다.
- 게임 화면이 실제 KakaoTalk WebView에서 잘리고 터치가 씹히지 않는지는 기기로 확인해야 합니다.
- 기존 서비스 워커 `sw.js`의 `/` 캐시 정책은 변경하지 않습니다. 실험용 진입 화면의 오프라인 접속은 보장하지 않습니다.

## 테스트

`npm run typecheck`, `npm run build`, `npx playwright test e2e/fullscreen-play.spec.ts`

브라우저 자동화에서는 실제 카카오톡 UI·Android 탐색 표시를 검증할 수 없습니다. 실기기에서 전체화면 진입 후 게임 탭·턴·팝업 터치, Android 종료 제스처를 확인하세요.
