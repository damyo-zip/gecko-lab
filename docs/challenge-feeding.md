# 도전 완료 수만큼 매 턴 먹이 면제

도전 최초 완료 1개마다 매 턴 1마리분의 급여를 무료로 처리한다. 슬롯 구매/배정/장착이나 별도 보상 카운터는 없다. 칭호와 같은 영구 기록의 **서로 다른 알려진 도전 완료 수(0~5개)**를 사용한다.

| 생존 보유 개체 | 완료한 도전 | 무료 급여 | 재고에서 필요한 사료 |
| --- | --- | --- | --- |
| 8마리 | 0개 | 0마리 | 8개 |
| 8마리 | 3개 | 3마리 | 5개 |
| 3마리 | 5개 | 3마리 | 0개 |
| 0마리 | 5개 | 0마리 | 0개 |

## 실제 처리

- `lifecycle.foodDemand`가 생존 보유 수, 실제 면제 수, 필요 사료, 부족분을 함께 계산한다. `max(0, 보유 수 - 완료 수)`를 공통 턴 버튼·부족 경고·자원 관리·컬렉션 컨디션/전체 목록·대시보드·도전 보상 안내에서 사용한다.
- 기존 하트 오름차순/동률 고유 ID 순서를 유지한다. 먼저 완료 수만큼 무료로 급여하고 나머지는 재고 사료로 급여한다. 무료 급여도 `lastFedDate`를 갱신하고 하트를 최대 5까지 1 회복한다. 무료분에 사료를 차감하거나 재고를 추가하지 않는다.
- 무료분과 사료가 모두 부족한 개체만 기존 하트 −1/0이면 폐사 규칙을 따른다. 같은 턴의 `lastProcessedTurn` 재처리 방지도 유지한다.
- 턴 시작의 생존 보유 개체가 대상이다. 알·수령 전 새끼·판매·폐사·외부 부모는 소비량/면제 수에 포함하지 않는다. 해칭/아성체/성체와 휴식/은퇴 상태는 기본 1마리 1식이다.
- 기존 순서인 급여 → 자연사 → 산란/부화 → 성장 → 상점 갱신을 보존한다. 따라서 이번 부화로 얻은 보상은 **다음 턴 급여부터** 적용한다. 수령 전 부화 결과를 무료 급여 개체로 등록하지 않는다. 무료 급여도 노령 자연사를 막지 않는다.

## 저장 호환

저장 v10/규칙 4의 형식은 그대로다. 기존 완료 기록의 `reward.feedExemptionSlots: 1`은 구세이브·최초 달성 증거를 보존하기 위한 필드명일 뿐이며 슬롯 배정에 사용하지 않는다. 기존 `challengeFeedSlots` 접근자는 호환용으로만 남고 실제 계산처럼 서로 다른 완료 수를 반환한다.

기존에 완료한 도전은 즉시 면제 자격으로 인정되며 **앞으로 진행하는 턴**의 급여량에 반영된다. 과거 사료 소비를 환급하거나 저장 중 재고를 조정하지 않는다. 완료 기록이 없는 이전 세이브는 면제 0이고 새 게임은 기존처럼 기록을 초기화한다. 이름 변경·분양·폐사·목표 변경으로 완료 기록이 지워지지 않는다. 같은 도전을 다시 달성하거나 같은 턴을 재처리해 면제 수가 늘어나지 않는다.

## 변경 범위

급여 엔진은 `src/game/hardcore/lifecycle.ts`의 필요량/실제 차감 처리만 확장했다. 도전 완료 판정·유전·표현형·이미지·부화/수령·상점 가격·화폐·저장 검증 규칙은 보존한다. `challenges.ts`의 기존 접근자는 완료 수 기반으로 맞추고, 보상/컨디션/상세/자원 관리/턴 버튼 UI의 설명을 실제 동작과 일치시켰다.

## 검증

- 관련 단위 **70개 통과**: 신규 급여 13개 + 기존 수명 38개/도전 11개/칭호 8개. 새 테스트는 0~5개 완료, 보유 수 미만/이상/0, 저하트 우선, 무료 급여 회복, 부족 시 기존 폐사, 같은 턴 재처리, 정확한 실제 사료 소비, 부화 보상의 다음 턴 적용, 수령 전후 대상 수, 구세이브/JSON 복원·판매·목표 변경·중복 기록 방어·새 게임·자연사 보존을 검사한다. 신규 13개는 독립 세이브 복사로 다시 통과했다.
- 기존 도전의 '급여 부족 시 기록 보존' 검사는 이제 한 마리를 무료로 보호하므로, 낮은 하트 개체가 여럿인 실제 부족 상황으로 수정했다. 무료분 외 개체의 폐사와 달성 기록 보존을 계속 검증한다.
- TypeScript 검사와 프로덕션 빌드 통과.
- 실제 모바일/PC Chromium **36개 시나리오 통과**: 신규 급여 면제 6개, 도전/미리보기 12개, 칭호 4개, 전체 개체 관리 10개, 공통 UI/턴 4개. 복원한 완료 기록으로 실제 `10마리 - 완료 2개 = 사료 8개` 차감, 네 탭의 동일 부족 경고, 재고 구입과 다음 급여, 무료 급여만으로 3마리 유지/남는 면제량 미적립, 실제 부화 보상의 다음 턴 적용과 새끼 수령 후 대상 증가를 확인했다. 새 테스트를 위해 다른 전체 테스트를 반복하지 않았다.
- 360~430px에서 기존 미리보기/목록/공통 UI가 유지되고 새 보상·부족 경고가 정상 동작했다. [390×844 실제 보상 화면](challenge-feeding/rewards-390.png). 실물 기기/Safari 검사는 수행하지 않았다.
