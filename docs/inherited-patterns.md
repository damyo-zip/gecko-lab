# 유전 형질 → 실제 무늬 → 한국어 자동 명칭

새 매물과 새로 수정되는 자손에 `appearanceVersion: patterns-1`을 적용합니다. 부모의 대립유전자 → 표현형 수치 → 부위별 픽셀 도형 → 도형의 관찰값 → 명칭 순서입니다. 이름으로 외형이나 자손을 생성하지 않습니다. 원화 PNG를 바꾸지 않고 96×96·8레이어 렌더러를 확장했습니다.

## 구현된 표현

| 구분 | 실제 외형과 판정 |
| --- | --- |
| 패턴리스 | 등·측면 패턴이 적은 피부. 기존 원화의 조명·질감은 남음 |
| 플레임 | 등 중심 크림 패턴, 측면·사지 표현이 낮음 |
| 할리퀸 | 실제 측면 26%·사지 16% 이상 |
| 익스트림 할리퀸 | 실제 측면 55%·사지 32% 이상. 일반 할리퀸보다 넓은 무늬 |
| 트라이컬러 | 기본·보조·크림 영역이 각각 10% 이상, RGB 색 거리 65 이상 |
| 타이거 / 브린들 | 몸통·목의 어두운 횡단 띠 / 구불구불 끊어지는 띠 |
| 파셜 핀스트라이프 | 실제 등 선 중 한쪽 이상 32% 이상 표현 |
| 풀 핀스트라이프 | 좌우 등 선 모두 끝에서 끝까지 100% 연결, 내부 끊김 0. 높은 유전 점수만으로 판정하지 않음 |
| 쿼드 핀스트라이프 | 풀핀 + 양쪽 측면 선의 실제 연결·최장 연속 구간 각각 90% 이상 |
| 드리피 | 밝은 패턴의 아래 방향 갈래 3개 이상. 단순 노이즈가 아닌 연결된 가지와 음영 |
| 화이트월 | 연결된 밝은 측면 띠가 몸통 피부의 20% 이상 |
| 달마시안 / 슈퍼달마시안 | 실제 배치된 분리 반점 12개 / 48개 이상. 수량·크기·좌표는 개체별 고정 |
| 레드 / 오렌지 / 옐로 / 크림 / 다크 | 유전 발색·명도와 팔레트. 같은 색군에서도 발색과 명도가 연속적으로 변함 |

**모든 수치는 96px 게임 판정 기준입니다. 업계의 합의된 수치나 실제 단일 유전자 확률이 아닙니다.** 반점 기준도 축소 픽셀 표현용이며 실제 개체의 점 개수 기준을 그대로 옮긴 것이 아닙니다. 아잔틱은 회색 팔레트, 릴리화이트는 높은 밝은 패턴 면적을 우선합니다. 파이어다운은 표현만 바꾸며 이름은 정규 파이어업 외형을 기준으로 유지합니다.

## 유전과 이름

- 기존 `PolyGenome v1`의 **60개 좌위·10개 형질·부모별 한 대립유전자 전달**을 그대로 사용합니다. 새로운 우성/열성 ‘풀핀 유전자’ 등을 만들지 않았습니다.
- 기존 `pinstripe` 좌위 6개를 3개씩 나눠 좌우 연결성을 계산합니다. `flank`, `cream`, `harlequin`, `contrast`, `dorsal`, `spots` 좌위의 여러 사본이 측면 연결, 드리피, 화이트월, 사지, 띠 복잡도, 반점 크기 등에 영향을 줍니다. 이런 부분집합 효과와 다면발현은 **게임용 근사 모델**입니다. 형질 간 상관이 생기며 모든 표현을 독립적으로 조절할 수 있는 모델은 아닙니다.
- 돌연변이 없이 감수분열·분리와 개체 고유 시드에 따른 도형 변동을 사용합니다. 부모의 시드·명칭·완성 픽셀을 자손에게 복사하지 않습니다. 세대 수 자체로 형질을 올리지 않습니다.
- 렌더러와 명칭 판정은 **같은 도형의 관찰값**을 사용합니다. 원본 `crest.png`가 몸통의 밝은 얼룩도 포함하므로 새 모델은 실제 외곽 크레스트만 구조로 보호하고 몸통 얼룩은 개체별 피부로 다시 표현합니다. 기존 외형 모델의 픽셀은 그대로 유지합니다.
- 대표명은 `유전 모프 + 색군 + 기본 패턴` 순서입니다. 예: `레드 트라이컬러 익스트림 할리퀸`. 핀·드리피·화이트월·달마시안은 별도 추가 특징입니다. `익할`, `트익할`, `풀핀`, `쿼드`는 규칙 파일의 별칭이며 무작위 상품명이나 독립 모프가 아닙니다.
- 컬렉션·상점은 대표명을 짧게 표시하고 상세·교배·혈통·부화 결과에서 전체 특징을 확인합니다. 상점 부모 창에는 관찰 가능한 추가 특징만 표시하며 숨은 보인자 정보를 공개하지 않습니다. 컬렉션에서 신규 패턴·색군 필터로 선별할 수 있습니다.

## 유지되는 저장·가격·게임 규칙

저장 v7과 기존 유전체 구조를 유지합니다. 외형 버전만 새 값을 추가했으며 계산된 도형·명칭은 재현 가능한 파생 데이터라 저장하지 않습니다. 이전 앱은 새 외형 버전을 알지 못하므로 새 백업을 이전 앱으로 되돌려 읽는 것은 지원하지 않습니다.

- 이전 `legacy-1`·`5.0` 개체, 이미 수정된 배아, 가족 매물 스냅샷은 외형·가격·유전형·시드·판매 이력을 보존합니다. 저장 읽기에서 새로운 가상 유전자를 생성하지 않습니다.
- 정식 v7에서 앞으로 생성하는 배아는 부모 둘 모두 기존의 60개 좌위를 보유하면 새 모델을 사용할 수 있습니다. 부모 외형은 그대로입니다. 가상 유전체가 없는 과거 개체와의 교배는 기존 평균·변이 모델을 유지하며 새 패턴을 확정된 유전 결과처럼 표시하지 않습니다.
- 기존 멘델·보인자 추론·안전 차단·근친 차단, 1턴=7일, 12턴 성체, 슬롯 2칸·교배+2턴 한 번 산란, 산란+4턴 판정·성장·수명 규칙을 변경하지 않습니다.
- 가격은 기존 유전 모프 기준가·공개 보인자 근거·성별·성장·부모 기록을 재사용합니다. 새 외형은 기본 일반형 기준가에 **실제 무늬 면적, 최장 핀 연결, 반점 수, 대비**를 각 한 번씩 반영합니다. 할리퀸/풀핀 등의 명칭 프리미엄을 추가하지 않습니다. 새 평가 기록은 시장 버전에 `/patterns-1`을 붙이고 이미 구매한 가격과 판매 기록을 바꾸지 않습니다.
- 가격·품질·수요 가중치는 임시 게임 모델입니다. 검증된 국내 거래가·희소성 통계를 확보했다고 주장하지 않습니다.

## 주요 코드와 아트 교체 계약

- `genetics/advanced/pattern-traits.ts`: 기존 상속 좌위에서 부위별 형질을 계산.
- `phenotype/model.ts`, `rules.ts`, `names.ts`: 표현형 계약, 수정 가능한 수치·별칭·가격 가중치, 명칭 판정.
- `engine/pattern-plan.ts`: 부위별 도형·연결선·반점·관찰값과 최대 128개 LRU. React·DOM·게임 턴에 의존하지 않음.
- `engine/render.ts`: 기존 원화 명암을 유지한 피부 팔레트·도형 합성. 새 경로 `2.1.0`, 기존 경로 `2.0.1`, v1 유지.
- `game/hardcore/appearance.ts`, `adapter.ts`, `market.ts`: 유전·렌더러 경계, 화면 공통 명칭, 관찰값 기반 가격.
- `/lab/patterns`: 14개 명시적 가상 유전형의 실제 Canvas 비교. 이 예제들은 매물 생성이나 자손 유전에 사용하지 않음.

양쪽 등·측면 라인을 기존 **한 장의 옆모습에 투영**합니다. 네 라인은 보이지만 실제 양쪽 측면을 동시에 보여주는 정확한 해부학적 자세는 아닙니다. Phase 3 수준의 아트 개선에는 양쪽 등 능선·측면을 구별하는 원화/마스크와 새 외형 버전이 필요합니다. 그때 `PatternTraits → PatternPlan → PatternObservation` 계약을 유지하고 기존 버전은 동결할 수 있습니다.

## 검증과 실제 캡처

`node scripts/pattern-report.mjs`는 실제 렌더러의 96px·정수 4배 PNG, 동일 유전형 12시드, 기존 6프리셋 해시, 3개 고정 시드의 관찰형 선택교배/무선별 대조군 기록을 `inherited-patterns/report.json`에 저장합니다. 실험은 집단의 대립유전자 선별 효과를 보는 도구이며 게임의 근친 차단을 해제하지 않습니다. 부모 선별은 숨은 대립유전자나 잠재 점수가 아니라 실제 렌더된 선의 연결·연속 길이를 사용합니다. 64마리씩 10세대의 3개 고정 시드에서 풀핀 비율은 초기 0%에서 선별군 98.4%·79.7%·89.1%, 무선별 대조군 모두 0%였습니다. 이는 해당 게임 모델·시드·표본의 실험이며 현실 교배 확률이 아닙니다.
